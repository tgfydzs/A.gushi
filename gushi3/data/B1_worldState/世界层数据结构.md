# 世界层数据结构，使用、创建、注意点
## 据文件使用json格式
## 结构示例：
    {
        "规则组1": {
            "世界规则列表": [],
            "世界状态列表": [],
            "世界知识列表": []
        }
    }
## 最外层保持标准字段，内部为列表，列表内部遵循单一语义单元（描述一件事情），为后续可能的向量化留足空间
## 一个文件存多个组


# 字段解释

## 规则组：
### 该字段不会参与到引擎中，无实际意义，是编辑时的区分辨识符


## 世界规则列表（list）
### 用途：世界基本规则，是既定事实，类似数学，会就是会不会就是不会。
### 通常是存一些定死的，是世界基本规则，但又需要额外声明的（ai理解时无法直接确定的事物），例如：
    "世界规则列表": ["战力到达筑基初期，力量有百鼎之力", "实力划分：锻体、练气、筑基、金丹、元婴、化神、炼虚、合体、大乘、渡劫"]


## 世界状态列表（列表）
### 用途：一般存放世界演变时间点时间线，和有一定变化但按固定规则，写明变化和依据的规则。世界演变时会参考这个。总结：剧本节点
### 类似一个剧本，里面预先设定了时间线，该字段仅传入导演层，供旁白使用
    "世界状态列表": ["公元0年，神圣帝国建立---公元204年，神圣帝国像兽族开战---公元299年，兽族宣布为神圣帝国附属国", "当位于神圣帝国中心的神像祭坛被破坏，神圣帝国的大主教将会变回原型"]

## 世界知识列表（list）
### 用途：世界级别，最杂的列表，该列表会不断演变
