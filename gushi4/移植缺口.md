# gushi3 → gushi4 移植缺口对照

> **用途**：gushi4 是把 gushi3 的层按「信息性质」重划而成。这份表逐条核对**重划时掉了什么**，
> 供修复时一行一行划掉。
>
> **基线**：`gushi3/层级职能梳理.md` —— 它是对着代码逐条核过的现有系统全量清单（F01–F77），
> 比两个版本的文档互相印证可靠。
>
> **方法**：五路并行审计（按层切片），每条结论都要求落到 `file:line`；
> 主会话对其中后果最大的一批**独立复核过**。
>
> **核实标记**：
> - ✅ = 主会话逐行核过（`grep`/读代码确认）
> - ◻ = 审计报了、未独立复核（修之前自己再看一眼）
>
> **档位**：`原样` / `改名` / `降级`（还在，但判据、边界或失败退路被削） / `丢失`（无对应物） / `新增`

---

## 摘要：一个统一的形状

**gushi4 每删掉一条确定性规则，都没有给它接上替代品。**

gushi3 的可靠性来自「纯规则兜底」那一层（P1：状态维护、调度、判定不给 LLM）。
gushi4 按信息性质重新分层时，把这些规则**连同它们的失败退路**一起删了，理由各自成立，
但**替代者没有被要求接管那份职责**：

| 删掉的确定性规则 | 交棒给谁 | 交棒时漏了什么 |
|---|---|---|
| N8 的耗时聚合 + 100 年截断 | L3 的 `本轮耗时分钟` | 尺子（段数×每段÷方式）与**天花板** |
| N7 的 `level`/`mask` 概率传播 | L1 的「传到」名单 | Python 兜底（旧结构来时**一句 WARNING 了事**） |
| N3 按 scope+距离的二次过滤 | 「判断权交回 L1」 | **同时新引入了 scope 枚举并声称代码强制执行**，实际没执行 |
| N3 作为独立调用的「审批权」 | R3 的补漏 | 「在名单里但不发声」这个**合法状态**消失了 |
| N2 的 `new_context()` | 无人接管 | 事件上下文**永不翻篇** |
| `{移动}` 标记 + 交互式导航 | 网页点地图 | **终端**没有替代物 |

## 1. 真正丢了东西的（按后果排）

### 1.1 时钟没有上界了 ✅

| | |
|---|---|
| gushi3 | `gushi3/common/N8_time.py:33` `MAX_DECLARED_MINUTES = 52_560_000`（100 年），超限截断并 WARN |
| gushi4 | `gushi4/common/R2_time.py:51-61` 的 `clamp`、`gushi4/common/L3_settlement.py:495-505` 的 `_parse_minutes`——**结尾都是 `return max(1, v)`** |
| 残骸 | `gushi4/common/base_cnf.py:226` `QUICK_DECLARED_MINUTES_MAX` 还在，但那是 S1 的，**没人读** |

**症状**：L3 对"我闭关一千年"随口给个大数，`game_clock.advance()` 照单全收，时辰制直接显示「（N 千日后）」；
之后世界状态与 NPC 记忆相对玩家时间全部错位，**不可自愈**。

**修**：在 `R2_time.clamp`（或它上游）加一个天花板，并把常量做成配置项（世界观的"最大单轮跨度"是世界观的事）。

### 1.2 事件上下文永不清空 ✅

| | |
|---|---|
| gushi3 | 新事件时 `gushi3/src/test/N2_contextRetrieval.py:144` 调 `event_context.new_context()` + `related_npc.new_list()` |
| gushi4 | `gushi4/Schema/Context_sch.py:44` 的 `new_context()` **注释还写着"一般用于事件层"**，但生产链路（`gushi4/common/engine.py`、`gushi4/common/game_controller.py`）**一次都不调**；只在测试里被调（`src/test/smoke_test.py:506`、`src/test/diag_reasoning.py:116`） |
| 新事件只做 | `gushi4/common/L1_perception.py:231` → `event_layer.reset()`，它**不动** `event_context` |

**连带失效**：`_resolve_is_new` 的防死循环护栏（`gushi4/common/L1_perception.py:326-330`）判据是
`ctx_len <= 事件_最小上下文长度`。gushi3 里每次新事件把 `ctx_len` 归零，所以这条守的是**每个事件的头两轮**；
gushi4 里 `ctx_len` 只增不减，它只守**整局游戏的头两轮**——**永久空转**。

**症状**：事件**永不翻篇**；L1 的"对话上下文"是全量历史（`L1_perception.py:203` 传整份 `event_context.context`），
token 与延迟随游戏时长线性增长；`event_context` 与 `global_context` 生命周期坍缩为同一个（违反 gushi4 自己写的 P10「三种上下文分离」）。

**修**：把 `new_context()` 接回 `is_new_event=true` 分支。

### 1.3 `scope` 只写不执行（三处说法互相矛盾）✅

引入 `scope` 枚举（D8）的**理由原话**（`gushi4/Schema/Event_sch.py` docstring）：

> 「枚举是确定性判断，**可以放在纯代码层（R3）强制执行**」

| 谁在说 | 说了什么 | 属实吗 |
|---|---|---|
| `gushi4/Schema/Event_sch.py:19-26` | 五条「R3 判定顺序（**硬约束，LLM 不可违反**）」：hidden→谁都不给 / involved→无条件给 / private→只给 `直接对象` / group→同势力 / public,area→走距离 | ❌ **代码里没有** |
| `gushi4/prompt/L1_perception_sys.txt:97` | 「`scope=private` 时，代码**只放行** `直接对象` 里的人」 | ❌ **代码里没有** |
| `gushi4/common/R3_perception_filter.py:112-159` | `enforce()` 实际只做三件事：`hidden` 清空 / 名字防幻觉 / `involved` 补漏 | ✅ |
| `gushi4/common/R3_perception_filter.py:163` | `is_hard_constraint()`——**专门用来执行这条硬约束的函数** | ❌ **全仓零调用**（只有定义） |

**症状**：判 `private` 不会真的挡住名单外的旁观者。而 `Event_sch.py:52-56` 自己写着误判过宽的代价是
「秘密进了别人的观察表/记忆表，**不可逆**，而且不会报错」。
反过来，L1 prompt 里那条警告（"判了 private 却让直接对象留空 → 没有任何人能收到感知"）**是假警报**——
代码不执行，所以消息不会因此丢，只会漏。

**对照 gushi3**：gushi3 也**没有**代码级 scope 执行（N3 的 `.py` 里连 `scope` 这个词都没有）。
差别在于 gushi3 把判断交给 N3 的 prompt，而那张 prompt 带着实打实的**节点/区域/城市三级可闻度表**
（`gushi3/prompt/N3_informationFiltering_sys.txt:29`：「同一节点 → 感知全部；同一区域上级 → 只感知大声/公开；不同城市 → 不可感知」）。
gushi4 把这张表也删了，换成「范围由你判断，不要套公式」。

**结论**：这不是"gushi3 有、gushi4 丢"，是 **gushi4 新引入了枚举、承诺了代码强制执行，然后没做**。

**修**（二选一，不能继续三处矛盾）：
- (a) 把 R3 的 scope 过滤补回来（至少 `private`→只放行 `直接对象`，这是唯一有"不可逆"代价的一档）；
- (b) 把 `Event_sch.py` 的 docstring 和 L1 prompt 改成实话。

### 1.11 移动的裁决权落到了「会读 NPC 干预的那一层」✅（**五路审计都没抓到的第 11 条**）

> 发现路径：实测。玩家在游戏里想离开宗门，游戏告诉他"出山令牌都没有"。

| | |
|---|---|
| gushi3 | 移动 = N6 的玩家增量**直接写位置**（`层级职能梳理.md` F35：自由文本移动由 N6 的玩家增量完成，**去向即到达**）。NPC 说什么都**不影响你人在哪** | 
| gushi4 | 位置改由代码落（D18，**这个方向是对的**），但落坐标**依赖结算层给的 `去向`/`行程`**（`gushi4/common/game_controller.py:570-594`）。而结算层的输入里**有 NPC 的对白**（`gushi4/common/L3_settlement.py:312` 的 `对白` 字段） |

**实测证据**（`gushi4/log/gushi4.log` 第 1 轮 + 服务端 `/api/history`）：

| 环节 | 实际内容 |
|---|---|
| 白鹤（角色层）说的 | 「你一个炼气中期的杂役，**出山令牌都没有**，这个时辰往山门走…」 |
| 白鹤的**动作意图** | **`无`**——"站在阶上继续问话"（日志原文） |
| 结算层的旁白 | 「叶尘停步，转身拱了拱手，**站定未动**」，耗时 **+2 分** |
| 位置 | 日志里**没有 `🚶 行进` 那一行** → 位移为零 |
| 世界数据 | `data/` 全库 grep「令牌」只命中**两件物品**（散修凡人的旧令牌纪念品、玄清宗主的禁制令牌）；世界规则列表六条里**没有**任何出山规矩 |

**没人动手，没人拦路。NPC 只是问了一句话，结算层就把玩家判成"站定未动"。**

**三条链让它变硬**：
1. **角色层没有"权威等级"**——它是最不该发明世界规则的一层（它连世界都看不到），但它可以**断言**世界事实，没有任何环节区分"白鹤的猜测"与"世界规则"。
2. **结算层的输入里有 NPC 对白**，于是把它当成了情境约束。
3. **一次幻觉进了上下文就永久成立**——下一轮 L2/L3 都读到"出山令牌"，会继续承认，**没有代码或数据能反驳它**（自我强化）。

**为什么这是 gushi4 特有的**：gushi3 的移动是**写盘动作**，NPC 的台词只影响叙事、不影响位置。
gushi4 之后，**"我能不能走"从写盘动作变成了结算层里的一个叙事判断**——

> **移动的裁决权落到了唯一会读 NPC 干预的那一层手里。**
> 白鹤能拦住玩家，不是因为他强，是因为他的台词进了 L3 的输入。

⚠️ 这条比 §8 里"去向不持久"更根本：**即使去向持久了，只要裁决权还在那一层，NPC 依然能靠一句台词把你钉住。**
修法见 `新版本需求与实现路径.md` 的 `R-b·9`（NPC 言语不构成客观拦阻）、`R-d·3`（「在路上」是状态不是每轮重新声明的意图）、`R-d·9`/`R-d·10`（移动只被客观拦阻中止，裁决权不落在会读干扰的那一层）。

### 1.12 私密信息被广播给事件名单里的**所有人** ✅

> 发现路径：实测。玩家"对白鹤使用传识"（一对一私密传念），**四个人一起回应了**。

**一手证据**（`gushi4/log/gushi4.log` 第 2 轮，同一次调用链）：

| 层 | 输出 |
|---|---|
| L1 | `L1 结果：scope=private 锁定=4 感知=4` —— **L1 判对了**（private），只给白鹤写了感知 |
| R3 | `R3：involved 漏感知 ['玄清…','云逸…','柳明溪…']，已用事实文本补齐` —— **另外三个人被塞了** |
| L2 | `L2：4 个 NPC 并行` —— 四个人都回应了一条私密传念 |
| R1 | `R1：scope=private，本轮不产生传闻` —— ✅ **同一轮里两个规则层对同一条 private 给出相反处理** |

补的文本是 `{玩家名}（玩家）对你说：{玩家原话}`（`gushi4/common/L1_perception.py:269`）——
**"传识"这个语境整个丢了**，那三个人收到的**字面**就是"玩家**对我说**：…"。
所以柳明溪会答"韩家村出身的同门……宗门里就一个——那个天天在落霞坪扫地的师兄？"：
**他在回应一条本该听不到的传音，而且是按"被当面告知"来回应。**

**根因（设计层，不是实现 bug）**：`gushi4/Schema/Event_sch.py:19-26` 写着五条判定，而
**代码只实现了第 1 条和最宽的第 2 条**（3/4/5 一条都没有）：

```
1. scope == hidden   → 谁都不给                                  ← 实现了
2. npc 在 involved 里 → 无条件给（无论多远、scope 多严）          ← 实现了，最宽
3. scope == private  → 只给 direct_target                        ← 没实现
4. scope == group    → 只给 involved 里同势力的                  ← 没实现
5. public / area     → 走距离判定                                ← 没实现
```

**「无论 scope 多严」这七个字就是漏洞的正式写法**——`private` 按这个顺序**不可能**生效，
因为它永远排在 `involved` 豁免之后。

**gushi3 对照**：`gushi3/prompt/N3_informationFiltering_sys.txt` 有两节正好治这个——

- 「## 6. **候选NPC ≠ 收到信息**：输入NPC只是候选，需根据对话对象、交流方式、是否公开、位置关系筛选」
- 「## 7. 交流方式」表：**私密 → 仅目标NPC**；公开 → 事件NPC + 同区域NPC；普通 → 当前NPC > 事件NPC > 位置NPC

**gushi4 把这两条都删了**，换成"名单内的人无论如何都知道"。

**放大效应**（与 §1.11 同一个形状）：`involved` 只增不减（§1.8）⇒ **此后每一条消息——包括每一条私密消息——
都会发给所有进过这个事件的人**；他们一回应，内容就进了 `global_context` ⇒
**私密信息永久变成公开知识**；下一轮 L1 看到他们在回应，又把名单留着。**自我强化，无可反驳。**

⚠️ 这条是 §1.3（"scope 只写不执行"）的**具体后果**，但根因不同：§1.3 是"承诺了没做"，
本条是**设计文字本身就把它排除了**。修 §1.3 的文档还不够，得改判定顺序。

**修法**（最小一处，一行原则）：
> **R3 只许做减法，不许做加法。** 可以**删**（防幻觉、执行 hidden），**永远不许新增收件人**。

唯一的加法点就是那整块「involved 漏感知补齐」（`gushi4/common/R3_perception_filter.py:150-157`）。
删掉它，这个类别的漏洞全灭，并顺带补上 `I-07`（"在名单里但不发声"必须是合法状态）。
另加一处把 `private` 真正执行；**没填 `直接对象` 时保留 L1 写的那份、不额外增删**（不要回退成"发给所有人"）。
需求见 `新版本需求与实现路径.md` 的 `R-b·6` / `R-b·11` / `I-18`。

## 8. 建议的修复顺序

### 第一批：确定性规则的替代品（小、纯代码、可离线验证、不依赖 LLM 自觉）

1. **时钟加天花板**（§1.1）——`R2_time.clamp` 或上游，常量做成配置项。
2. **接回 `new_context()`**（§1.2）——`is_new_event=true` 时清事件上下文，顺带救活 F12 的护栏。
3. **把 `triggered_rules` 喂回 B1a**（§1.5），**把叙事缓存写回并喂回 B1b**（§1.4）。
4. **心跳/R4 的调度状态入档**（§1.10），并让 `!!` 能回滚它们。
5. **`dead_reserved_keys()` 接进编辑器保存路径**（§3.4），让"声明了没人读"当场可见。

### 第二批：`scope` 的三处矛盾必须收口（§1.3）

二选一：**(a)** 把 R3 的过滤补回来（至少 `private` → 只放行 `直接对象`，这是唯一有"不可逆"代价的一档）；
**(b)** 把 `Event_sch.py` 的 docstring 与 L1 prompt 改成实话。**不能继续三处互相矛盾。**

### 第三批：事件层归位 + 去向持久化（改动面最大，也是用户最初报的那个症状）

- **去向持久化**：行程单（目的地/出发地/出发时刻/预计总分钟）落到玩家状态，抵达即清。
- **事件层五项职责归位**：新事件认定 / 召集 / 踢出 / **散场遣散** / 玩家移动目标。
- 配套：`involved` 的释放规则（走远即踢）+ R3 强制补感知收窄（只补本轮 `add_npc` 的人）。

### 暂不动

- **NPC 位置冻结**（§1.6）：地图正在整体重做，**先确认 NPC 是不是有意做成静态锚点**。
