### 实现中发现的、需要你确认的三处判断

1. **L1 拿到了全员名册的「实力」字段**（§3.2 的输入表只写了"全NPC名单"）。
   理由：**"点名必达"要求 L1 能为任何一个被点名的人写失真**，而失真程度取决于
   观察者自己的修为——不知道对方是炼气还是化神，就写不出"他能不能看透你"。
   这与 L1 需要玩家真值是同一个道理。**不含任何 11 张表。**

2. **`当前状态CurrentState` 的归属被拆开**：L2 只写 8 张主观表，
   `当前状态`与`持有物`归 L3。`内心想法` 是 L2 交给 L3 的**判断依据**
   （"真给"还是"敷衍"），L3 据此写 `当前状态`（含`当前心情`）。
   ——这是 gushi3「内心想法 → 操作方向」那张表的原地搬家。

3. **B2 不写客观表**（与 L2 同契约）。代价：背景 NPC 无法真的移动或得到物品，
   背景活动只能表达为"观察/记忆"。换来的是一致性由结构保证，不用为后台
   再开一个结算通道。

| 层 | 平均耗时 | 平均推理token | 推理占输出 |
|----|---------|--------------|-----------|
| N2 | 3.3s | 477 | 91% |
| N3 | 6.7s | 1112 | 90% |
| N45 | 7.9s | 998 | 85% |
| **N6** | **9.5s** | **1444** | **67–96%** |

**单轮平均 ~27s，其中推理 token 占墙钟时间约 85%。**

### 这推翻了什么

| 原来的判断 | 数据后的修正 |
|-----------|------------|
| "NPC表全量喂入是延迟主因" | ❌ **错**。输入只有 1600–3900 token，处理很快；砍输入最多省 0.5s |
| "减层是核心优化目标" | ⚠️ **降级为待验证**。层数优化的是固定开销，推理量优化的是任务复杂度，**这是两个独立的轴** |
| "L2/L3 拆分能提速" | ⚠️ **这个理由删掉**。拆分的设计理由（客观状态跨实体）仍然成立，但性能理由不成立 |

**真正的第一杠杆是模型选型**——见 §3.8。

## 一、不变的原则

从 gushi3 继承，这些是已验证有效的核心，**一个字都不改**：

| # | 原则 | 说明 |
|---|------|------|
| 1 | **Python 负责** | 状态维护、调度、数据结构、Prompt 管理、JSON 解析 |
| 2 | **LLM 负责** | 事件判断、感知分发、推理、回应、导演叙事 |
| 3 | **LLM 无状态** | LLMClient 不存任何上下文，调用方全权管理 |
| 4 | **LLM 输出必须 JSON** | 统一 `safe_json_loads()` 四级降级解析 |
| 5 | **增量更新** | `{"增加":{...},"删减":{...}}`，只传变化 |
| 6 | **可撤回** | 每轮全量快照，`!!` 回滚 |
| 7 | **数据驱动** | 数值/名称/行为参数全部从世界配置读 |
| 8 | **不程序化叙事** | **世界必须能被 LLM 产出意外**——见下方「为什么不能用规则替代」 |

### 为什么不能用规则替代 LLM

小说里有**越级战斗**：弱者击败强者。如果实力对比可计算，强者必胜，玩家就能反推胜负，**没得玩**。

因此：
- 实力感知**不能**用等级差公式算——玩家会反推出实力对比
- 感知失真**必须**由 LLM 产出——"有时看得透、有时看不透"本身就是叙事
- 同理，但凡影响剧情走向的判断，都不能退化成确定性规则

**规则只用在"错了也不影响叙事"的地方**：位置在不在场、消息能传多远、时间怎么折算。

## 二、信息过滤：唯一的分层依据

### 2.1 判定规则

> **一个 LLM 调用只能属于一个信息域**（不得跨域）。
> 合并合法 ⟺ 合并后**每个输出字段的生产者，仍然只看得到它原本该看的**。

判定对象不是"两个职能长得像不像"，而是**生产字段 X 需不需要看那些对 X 禁止的信息**。

#### 这条规则回答"能不能合"，不回答"该不该合"

容易和 §3.8 混淆，必须分清：

| | §2.1 信息域规则 | §3.8 性能双轴 |
|--|----------------|--------------|
| 回答 | **能不能**把两个职能放进一次调用 | **该不该**合 / 拆 |
| 依据 | 安全性与正确性（会不会泄漏） | 收益（推理量 vs 固定开销） |
| 违反后果 | 泄漏，破设计原则 | 只是慢，或想得不充分 |

**同域的两个职能，合与拆都合法**——比如把 L1 拆成两次调用，两次都属世界域，规则允许。
合不合只看 §3.8 的账。

反之**跨域合并一律非法**，不管性能上多划算。

### 2.2 三个信息域

把全部调用点按信息**视角**分类，**只有三个域**：

| 信息域 | 内容 | 视角 |
|--------|------|------|
| **世界域** | 世界规则/状态 · 地点树 · 全NPC名单 · 幕后情报 · 事件现场 | 调度（全局俯瞰） |
| **角色域** | 单个NPC的11张表 · 它自己那份感知 | 扮演（单方主观） |
| **结算域** | 玩家实况 + 各实体的**客观侧**（持有物·位置·伤势） | 上帝（跨实体客观） |

> **唯一的跨域字段是"玩家实力"**：世界域的 L1 需要它才能产生失真（§3.2），
> 结算域的 L3 需要它才能结算战斗。其余字段都严格属于单一域。

**前台后台不是两种东西，是同一个域的不同触发时机。** 意味着"职能整合"的答案是：**同域的前后台职能共享一套契约**。

#### 为什么第三个域叫"结算域"而不是"玩家域"

原设计叫"玩家域"，理由是"只有写玩家的层才需要玩家实况"。但 §3.4 的交易问题证明这不够——

**结算层同时需要玩家实况和各 NPC 的客观侧**，因为它要做的是**跨实体的**判定。所以这个域的本质不是"玩家"，而是**上帝视角**：既看得见玩家的私密状态，也看得见所有实体的客观状态。

这个改名不是文字游戏，它改变了域的边界：

| | 旧定义（玩家域） | 新定义（结算域） |
|--|----------------|----------------|
| 内容 | 只有玩家实况 | 玩家实况 **+ 各实体客观侧** |
| 边界依据 | 实体是谁 | **信息性质**（客观 vs 主观） |

**边界依据从"实体"改成"信息性质"，是整个设计的枢纽**：

- 主观信息（记忆/信念/好感度/待解释）→ 只属于**角色域**，只有本人视角该碰
- 客观信息（持有物/位置/伤势）+ 玩家实况 → 只属于**结算域**，跨实体，必须上帝视角

这样 L2 拿角色域、L3 拿结算域，职责天然不重叠，也解释了为什么交易必须在 L3 结算（§3.4）。

### 2.3 失真感知（本设计的核心机制）

**问题**：NPC 该知道玩家多少？

**错误答案**（gushi3 的隐含做法）：玩家实力是客观字段，要么给要么不给。

**正确答案**：**每个观察者对每个事实持有一份失真的认知，失真程度由 LLM 判断。**

| 观察者 | 看到的"玩家实力" |
|--------|----------------|
| 低阶修士看高阶 | "气息深沉，看不透深浅" |
| 高阶修士看低阶 | "炼气期蝼蚁" |
| 同级 | "与我相仿，胜负难料" |

这就是**越级战斗的来源**——NPC 误判了对手。这不是 bug，是设计。

**实现**：L1 产出的不是客观字段，而是**每个 NPC 主观认知到的内容**。玩家的真实实力永远不进角色域。

**不给刻度**。不告诉 LLM "等级差大于 X 就看不透"——给了就变成可反推的公式。只给原则：

> 你对目标的了解程度取决于你自己的修为、见识、经验，以及对方是否刻意隐藏。
> 低修为者面对高修为者，往往只能感到"深不可测"。

## 三、分层结构

### 3.1 全貌

```
┌─ 关键路径（3 跳 · 跳数本身待验证，见 §八）───────────────┐
│                                                        │
│  L1 感知过滤层（世界域，1×/轮）                          │
│     决定：这轮发生了什么 · 谁在场 · 每个NPC感知到什么      │
│                                                        │
│              ↓                                         │
│  L2 角色层（角色域，每NPC1次，并行）                     │
│     决定：这个NPC怎么理解 · 怎么回应 · 主观状态怎么变      │
│                                                        │
│              ↓                                         │
│  L3 结算层（结算域，1×/轮）                             │
│     决定：客观状态怎么变（双方）· 全局旁白 · 本轮耗时      │
│                                                        │
└────────────────────────────────────────────────────────┘

┌─ 旁路（与 L1 并行发起，不占跳数）───────────────────────┐
│  S1 轻判断通道 → 移动倍数 · 声明时长                     │
└────────────────────────────────────────────────────────┘

┌─ 纯规则（0 耗时）───────────────────────────────────────┐
│  R1 地段传播  ·  R2 耗时折算  ·  R3 感知硬约束过滤        │
└────────────────────────────────────────────────────────┘

┌─ 后台（心跳触发，独立线程）─────────────────────────────┐
│  B1 世界线：规则触发（低温） ‖ 环境叙事（高温）           │
│  B2 角色幕后：NPC 自主行为 + 剧情级传播（与 L2 同域）     │
└────────────────────────────────────────────────────────┘
```

**关键路径 LLM 跳数：3**（gushi3 是 4）—— ⚠️ **这是假设，不是结论**，见 §八
**每 NPC 串行链：1 跳**（gushi3 是 2）
**结算域暴露面：1 次/轮**（gushi3 是 K 次）

### 3.2 L1 感知过滤层（世界域）

**这是"信息过滤"本体。** 它不再只是分发消息，而是产出**经过失真的感知**。

| 项 | 内容 |
|----|------|
| 频率 | 1×/轮 |
| 输入 | 事件上下文 · 全NPC名单 · **玩家真实实力/身份** · 玩家当前位置与在场外观 · 附近NPC{名,位,距离} · 幕后情报 · 世界状态 |
| **不拿** | ❌ 玩家持有物/描述（背景秘密）· ❌ 任何 NPC 的 11 张表 |
| 输出 | `is_new_event` · `在场NPC` · `关联NPC` · **`感知分发{名:失真感知文本}`** · `地段传播{msg,level,mask}` |

#### ⚠️ L1 必须拿玩家**真实**实力

这点容易搞反，但它是硬要求：**不知道真值就没法失真**。

要让 L1 写出"低阶修士看化神期只觉得深不可测"，它就必须知道对方真是化神期。
所以 L1 **持有真值**，但**输出里只有失真后的版本**——真值不落进 `感知分发`。

**这不是泄漏**，理由和 L3 一样：**L1 不产出任何自由文本形式的 NPC 内容**（没有对白、没有内心想法），
它产出的 `感知分发` 是**代码可逐条检查的结构化文本**，且内容本身就是失真的。

**硬约束由代码先做**（借鉴 gushi2 的 `is_hard_constraint`）：

| 硬约束 | 谁做 | 说明 |
|--------|------|------|
| 位置在不在场 | **纯代码** | 距离 > `NPC_附近距离_段` 的 NPC 不进候选 |
| 事件 scope 可见性 | **纯代码** | `hidden` 事件直接剔除 |
| `involved` 必感知 | **纯代码** | 锁定集里的 NPC 无条件获得感知（LLM 不可违反） |

LLM 只做**软判断**：失真程度、注意到哪些细节、措辞。

**输出体量控制**（本方案最大风险，见 §八）：
- 只对**锁定的 NPC** 产出感知（通常 1–3 个）
- 每份 ≤100 字
- 不在场的走 `地段传播`（概率）

### 3.3 L2 角色层（角色域）

**合并了 gushi3 的 N4/N5 + N6 的主观部分。** 一次调用完成「理解 → 回应 → 主观落实」。

| 项 | 内容 |
|----|------|
| 频率 | 每NPC 1 次，`ThreadPoolExecutor(max_workers=6)` 并行 |
| 输入 | **该NPC 11张表（截断后）** · **它自己那份失真感知** · 对话上下文 |
| **不拿** | ❌ **玩家实况**（一切对玩家的认知都来自 L1 那份失真感知）· ❌ 世界地点树 · ❌ 全NPC名单 |
| 输出 | `主观增量`（记忆/观察/信念/好感度/待解释）· `回应Response` · `内心想法InnerThought` · **`动作意图`**（"我打算把剑给他"） |
| **不写** | ❌ **客观状态**（持有物/位置/伤势）→ 那是 L3 的活 |

**为什么 L2 不碰玩家实况**：它产出自由文本对白，代码无法裁剪其中的泄漏。所以只能入口过滤。

**代价（明确接受）**：NPC 判断战斗结果时，依据的是**它自己（可能错误）的感知**，而不是玩家真实实力。这正是越级战斗成立的前提。

**产出「动作意图」而不是直接落实**：L2 看不到玩家实况，**无法验证玩家的声明**（详见 §3.4 的交易问题）。所以它只表达"我想做什么"，客观是否成立由 L3 判定。

### 3.4 L3 结算层（客观上帝视角）

**唯一持有玩家全量实况、也是唯一的客观状态写入口。** 合并了 gushi3 的 N6。

> 注意措辞：L1 也持有玩家的**实力**（用于产生失真，§3.2），但只有 L3 拿**全量**实况（含持有物、描述）。
> 玩家实力是唯一横跨两个域的字段——因为"失真"和"结算"两件事都需要它。

| 项 | 内容 |
|----|------|
| 频率 | 1×/轮（无NPC时处理玩家独处行为） |
| 输入 | **玩家实况（全量）** · 各 NPC 的**客观侧**（持有物 + 当前状态，**2 张表，不是 11 张**）· L2 产出的所有动作意图与对白摘要 · 感知 · 旁路给的耗时 |
| 输出 | `玩家增量` · **各NPC的客观增量**（持有物/位置/伤势）· `全局旁白[]` · `本轮耗时分钟` · **破裂观察注入** |
| **不产出** | ❌ 任何自由文本形式的 NPC 内容（无对白、无内心想法）→ **因此不泄漏** |

**输入为什么能从 11 张表砍到 2 张**：客观结算时，主观表只需要**写**不需要**读**——不需要知道这人的性格信念才去扣他一把剑。而"这人会不会真给"的判断，L2 已经做完了。

**输出为什么能从 6 张表砍到 2 张**：主观增量已由 L2 就地输出，L3 不再重复。

### 为什么客观结算必须是上帝视角

**物品转移、战斗伤害、位置变化本质上是「跨实体」的**，从任何单方视角看都不完整。

具体到交易：玩家说"我给100灵石，你把剑给我"——

- L2 看不到玩家实况，**无法验证玩家有没有 100 灵石**，只能信（NPC 在现实中同样看不到你的钱包）
- 如果 L2 擅自把剑扣了，L3 事后发现玩家付不起，**剑已经出去了，没人能收回来**（L3 当时拿不到 NPC 的表）

所以正确切法是**按信息性质分，不按实体分**：

| 信息性质 | 例子 | 谁写 | 为什么 |
|---------|------|------|--------|
| **主观** | 记忆 · 观察 · 信念 · 好感度 · 待解释 · 对白 · 内心想法 | **L2** | "我怎么想"，只有本人视角该碰 |
| **客观** | 持有物 · 当前位置 · 伤势 | **L3** | "世界实际怎样"，跨实体，必须上帝视角 |

这样交易校验天然解决：**L3 同时看到双方持有物，判定成立与否，双方一起变或一起不变。**

**交易破裂后 NPC 的反应**：L3 产出旁白 + 给该 NPC **注入一条观察**（"玩家掏不出灵石，交易当场破裂"），NPC 的反应在**下一轮**由 L2 自然发生。复用已有的「观察 → 感知」通道，零新机制。让 L3 去改 NPC 的情绪表反而更糟——那需要它理解 NPC 的心理状态，是 L2 的活。

**代价**：L3 的输入比纯玩家域版多了「各 NPC 客观侧」（2 表/NPC）。但相比 gushi3 的 N6（11 表/NPC），仍是大幅缩减。

### 3.5 S1 轻判断通道（旁路）

**不是层，是旁路。** 它不参与信息域划分——权限比任何一层都小（只看玩家输入）。

```
主链：L1 ──────→ L2 ──────→ L3 ──────→ R2耗时
旁路：S1 ──────────────────────────────↗
      ↑ 与 L1 同时发起，L1+L2 的时间远大于它 → 不占跳数
```

**入选条件（三条必须同时满足）**：

| 条件 | 为什么 |
|------|--------|
| 只依赖玩家输入 | 能并行发起，不占跳数 |
| 输出是标量/枚举 | 关推理后模型对结构化提取仍有把握，对自由文本没有 |
| 判错代价可控 | 错了最多时间算不准，不会毁剧情 |

**当前入选**：移动方式 → 时间倍数 · 玩家声明的时长 → 分钟。**一次调用产出两者**。

**明确落选的**：感知失真 · NPC回应 · 规则触发 · 环境叙事（都要叙事质量）；事件边界 `is_new_event`（判错清空上下文，代价太大）；意图标签（多一个不可靠信号源，不做）。

**必须能优雅降级**：旁路绝不能成为新的故障点。超时/失败 → 静默回落规则兜底：

| 失败项 | 兜底 |
|--------|------|
| 移动倍数 | 1.0（步行） |
| 声明时长 | 0（当没声明，走规则折算） |

因此**短超时 + 不重试**，与大模型层策略**相反**。

**数值必须夹取**：不推理时模型给数字更容易乱来（没有"想一下"来校准）。倍数夹到 `[0.1, 100]`，分钟夹到合理上限。

### 3.6 纯规则层

| 模块 | 职责 | 为什么是规则 |
|------|------|-------------|
| **R1 地段传播** | 消息在地点树扩散为传闻，`mask` 概率判定 | 错了只影响传不传得到 |
| **R2 耗时折算** | `活动耗时 + 移动(段数×每段÷倍数)` | 纯算术，不需要判断 |
| **R3 感知硬约束** | 位置/scope/involved 过滤 | **确定性判断，不需要 LLM** |

### 3.7 后台

| 模块 | 频率 | 说明 |
|------|------|------|
| **B1a 规则触发** | 心跳 1× | 温度 **0.3**（严谨因果链） |
| **B1b 环境叙事** | 心跳 1× | 温度 **0.9**（创意写作），与 B1a **并行** |
| **B2 角色幕后** | 心跳，**每组1×** | 与 L2 **同域同契约**，是角色层的"后台批次" |

**B1a 与 B1b 不合并**：它们并行跑，合并**不省任何延迟**，只会让 0.3 和 0.9 的温度需求互相打架。这不是信息过滤问题，是收益问题。

**B2 与 L2 的关系**：同一套**输出 Schema 和落盘代码**，prompt 分两份（在场需要"回应"，幕后不需要）。这是"职能整合"的落点。

### 3.8 模型选型：第一性能杠杆

**每个调用点两个独立开关：用哪个模型 · 开不开思考。**

当前端点支持关思考（裸 `requests` 直接塞进 payload，不需要 SDK）：

```python
payload['thinking'] = {'type': 'disabled'}
```

#### 模型选型 = 只需要一个开关

**所有层用同一个 DeepSeek 模型，区别只在开不开推理。** 所谓"极简模型"就是同一个模型关掉思考——
不需要另找一个模型，也不需要第二个服务商。

```
payload['thinking'] = {'type': 'disabled'}     # 裸 requests 直接塞，不需要 SDK
```

**关掉推理同时解决延迟和成本**：推理 token 按输出计费，实测占输出的 67–96%。
N6 那轮 `out=2594 reason=2485`，关掉后计费输出从 2594 掉到 ~109——**成本降约 20 倍**。

**而且推理消融实验（§八 阶段 1）用的就是这同一个开关**——实验机制和运行时配置是同一套，不用另写代码。

#### 为什么这是第一杠杆

数据（§零）：推理 token 占墙钟时间 **85%**，生成速度 ~170 token/秒。**延迟几乎全部来自模型"想"的过程**，而不是输入规模或层数。

| 手段 | 预期收益 |
|------|---------|
| **① 关思考 / 换非推理模型** | **~5x** |
| ② 降低每层任务复杂度（让它少想） | 中等 |
| ③ 减层 | 小（但 ① 之后会变大，见下） |
| ④ 削减输入（全表上限、记忆巩固） | **≈0，别指望它提速** |

**③ 有个反转**：一旦推理被干掉，每跳只剩固定开销（网络 + TTFT + 输入处理，约 1.5s）。那时 4 跳 vs 3 跳就是 6s vs 4.5s——**减层的价值要在关掉推理之后才兑现**。所以 ① 和 ③ 不是二选一，**有先后**。

#### 两个轴是独立的，不要混为一谈

| 轴 | 优化什么 | 方向 |
|----|---------|------|
| **层数** | 固定开销：网络往返 · TTFT · 重复读题 | 减层 → 合并 |
| **任务复杂度** | **推理量**：任务越单纯，想得越少 | 降复杂度 → 拆细 |

**这两个方向是相反的。** 所以不存在统一的"就该合并"或"就该拆开"——得看哪个轴的收益大。

数据支持"任务复杂度 → 推理量"（N2 简任务 477，N6 杂任务 1444），但**噪声极大**：N6 同一任务五轮的推理量是 `2485 / 1840 / 596 / 1363 / 934`，**差 4 倍**。内容本身比任务结构更能决定它想多久。

**结论：拆细能否降推理量，必须实测，且要跑够轮次。** 单看两轮会被噪声骗。

#### 每次调用的"推理底噪"

最简的 N2 任务也要 ~213 推理 token（读题 + 组织输出的固定成本）。一轮 4 次调用 ≈ 800 token 底噪，占总量约 **16%**。

**所以拆细不会被底噪压垮**——如果任务单纯化真能让每次少想一半，是划算的。

#### 判断某层该用哪档模型

> **哪些决策单元不靠推理也能做对？**

| 如果某层… | 那么 |
|----------|------|
| 不需要推理就能做对 | 用**非推理模型** → 快 10 倍 → **可以拆细**（反正便宜） |
| 必须靠推理 | 保留推理 → 慢 → **应该合并**（省固定开销） |

**S1 旁路天然属于左边**（输出标量，不需要想），所以它**默认关推理**。
其余各层属于哪边，靠 §八 的阶段 1 逐层实测——**一次只关一层**。

## 四、关键设计决策

| # | 决策 | 理由 | 放弃了什么 |
|---|------|------|-----------|
| D1 | 关键路径收敛到 3 层 | L1 = N2+N3（同属世界域）；L2/L3 按**信息性质**拆 N6 的活 | ⚠️ **层数本身待验证**（§八 阶段 2）。L2/L3 的拆分理由是设计性的，不是性能性的 |
| D2 | **失真感知**替代"公开/私密二分" | 二分法无法表达"看不透"，而看不透是越级战斗的来源 | — |
| D3 | 失真**不给刻度** | 给了刻度就变成可反推的公式，玩家能算实力对比 | 短期可控性（用 prompt 打磨换） |
| D4 | L2 完全不碰玩家实况 | 对白是自由文本，代码无法裁泄漏，只能入口过滤 | NPC 判战斗依据的是自己的（可能错的）感知——**这是设计，不是缺陷** |
| D5 | **客观状态（持有物/位置/伤势）统一由 L3 结算，L2 只出"动作意图"** | **客观状态跨实体，单方视角无法结算**——交易涉及两人，从任一方看都不完整；L2 看不到玩家实况就无法验证玩家声明，擅自落实会导致"剑给出去了、钱收不回来"。L3 同时看双方，才能"一起变或一起不变" | L2 不能就地落实客观动作；L3 输入多 2 表/NPC |
| D6 | 耗时放 L3 不放旁路 | "聊了多久"依赖实际对话内容，旁路看不到 | 旁路的免费并行 |
| D7 | 感知硬约束用代码 | 位置/scope/involved 是确定性判断 | — |
| D8 | 事件 `scope` 回归 | gushi1/2 的 public/area/group/private/hidden，比概率 mask 可控 | 事件层要配合产出 scope |
| D9 | B1a/B1b 不合并 | 并行不省延迟，温度冲突真实 | 一次调用的简洁 |
| D10 | **不用向量检索** | 见 §七 | 语义检索的灵活度 |
| D11 | 意图标签不做 | 多一个不可靠信号源，收益不明 | — |
| D12 | **L3 是唯一的客观状态写入口** | 一致性由结构保证，而不是靠各处自律 | — |
| D13 | **每个调用点两个独立开关：模型 · 思考** | 数据显示推理 token 占墙钟 85%，是第一杠杆（§3.8） | — |
| D14 | **层数不做成版本，做成配置** | 层数与推理量耦合，并行多版本是为未定的前提做两遍工（§八） | 一次性拿到"最终形状"的爽感 |
| D15 | **不用"减层"作为核心目标** | 层数优化固定开销、任务复杂度优化推理量，**是两个方向相反的轴** | 简单叙事（"层少了就快了"） |

> D5 的原始理由是"冲突仲裁是语义判断"——**这个理由不够**。
> 真正的理由是结构性的：**客观状态跨实体**。任何让单方视角落实客观变更的设计都会有这个洞，
> 这是信息过滤原则的必然代价，不是实现细节。
>
> D15 是这份文档里**最容易被违反**的一条。整场讨论的起点是"减层"，
> 但数据显示减层的收益要在关掉推理之后才显现。**先做快，再谈少。**

## 七、记忆管理：不用向量检索

**问题**：gushi3 只截 3 张表，另有 4 张（对玩家观察 / 好感度 / 信念 / 目标）**无上限无限增长**，而每轮全量喂给角色层。

⚠️ **注意：优化记忆不是为了提速。** token 数据（§零）显示输入只占很小一部分，砍输入最多省 0.5s。
记忆管理的真实收益是**三条别的**：

1. **防无限增长** —— 长跑必然溢出上下文窗口，是**崩溃风险**，不是性能问题
2. **控成本** —— 输入 token 是要付费的
3. **保质量** —— 记忆/观察表塞满陈年旧事，会稀释"最近发生的事"的权重

**为什么不上 RAG/向量化**：

| RAG 有意义的条件 | 本场景 |
|-----------------|--------|
| 库远大于上下文窗口 | ❌ 记忆 30 条、观察 20 条 |
| 相关性可判断 | ❌ **NPC 的表是"它自己"，全部相关**，检索出来还是全部 |
| 顺序无关 | ❌ **叙事强依赖时序**——"他上周答应我的"与"他今天反悔了"相似度极低，但必须同时在场 |
| — | ❌ 引入 embedding 服务、缓存、存档兼容（向量存不存？读档怎么办？）、切世界观要重建索引 |

**真解（按性价比）**：

1. **补齐硬上限** — gushi3 只截了 3 张表，`对玩家观察`/`好感度`/`信念`/`目标` **无上限无限增长**，而每轮全量喂给角色层。全部配上限，配置化。
2. **记忆巩固（摘要压缩）** — 超额时不丢弃，把最旧一批**压缩成一条摘要**。这符合本系统的"信息有损"哲学：NPC 本来就该记不清陈年旧事的细节。**放后台，不占关键路径。**
3. **条目瘦身** — 写入时限制记忆条目长度。
4. **按层裁剪** — L1 不需要任何 NPC 表。

**将来什么时候向量化才值得**：NPC 数量涨到几百个，或要做跨 NPC 情报检索。现在个位数到几十，太早。

**如果真要检索**：索引维度该是**结构化维度（谁/在哪/何时）**，不是 embedding 相似度。叙事记忆的天然索引是时间和人物。

## 八、验证计划

**总原则：不要用"版本"组织实验，用"配置"。**

层数和推理量是**耦合的**，不是平行的：层数决策依赖推理决策的结果（§3.8）。
并行做"3层版"和"4层版"等于**为一个还没定的前提做两遍工**。

层数应该是**配置**——L1 内部"合并成一次调用"还是"拆成两次"做成开关，先实现拆开的（保守、好调试），验证通过后再合并对比。

### 阶段 0：核心功能跑通（推理**全开**）—— ✅ 已完成

先不做任何性能实验，把 gushi4 核心做出来：L1 失真感知 + L2 角色 + L3 客观结算 + 旁路。

**推理全开是刻意保守的**——目的是先确认**新设计本身有效**：

| 要确认的 | 为什么 | 结果 |
|---------|--------|------|
| 失真感知能产出"看不透"（不是千篇一律） | 这是越级战斗的来源，是整个设计的枢纽 | ✅ 见下 |
| L3 能守住交易一致性（双方一起变或一起不变） | 这是拆 L2/L3 的**唯一理由** | ✅ 见下 |
| L2 只出"动作意图"、L3 落实，链路能闭合 | 新契约的核心 | ✅ |

**这阶段不测性能。** 一旦图快把推理关了，质量出问题时分不清是设计错了还是模型选错了，整个账就废了。

#### 实测（`python src/test/run_scenario.py`，8 轮剧本）

**① 失真感知确实在失真，而且不对称本身生成了剧情。**
玩家在落霞坪朝后山喊话，远处的化神后期宗主收到的感知是
"声息单弱，是外门弟子的底子，修为不过炼气"，他的回应是：

> 「三重禁制之下，你一个炼气弟子的声音能递到我耳边——先说说，你是怎么做到的。」

这正是设计要的东西：**不是"他该不该知道玩家"，而是"他凭自己的能力读出了什么、又困惑于什么"。**
同轮在场的金丹长老（**感知里没有"能穿透禁制"这件事**）则完全没往那个方向想，
只当弟子胡闹——同一个事件，两个观察者看到的东西不同。

**② L3 守住了交易一致性。** 玩家谎称拍出"一百块上品灵石"买长老的本命法宝：

```
玩家增量 {}   NPC增量 {}   破裂观察 ×2
旁白：["叶尘探手入怀，指间空落，掌上仍是那三块碎灵石。",
       "石阶上并无锦袋落下，白鹤的拂尘也未离手。"]
```

**双方一起不变**——这正是拆 L2/L3 的唯一理由，也是"L1/L2 只能相信玩家的声明、
L3 才验证得了"这条链路的直接证据。破裂后注入的观察会在**下一轮**由 L2 自然反应。

**③ 反向也成立。** L2 出「给予：取一瓶辟谷丹递给他」，L3 核对白鹤确实持有辟谷丹、
且这是不求回报的赠予 → 转移成立。**该成的成、该败的败。**

**④ 意外收获：跨轮记忆自然生效。** 玩家第一次捧出八块碎灵石、第二次改口说三块，
白鹤的回应是"三块？你方才捧出来的明明是八块"。

#### 阶段 0 暴露的问题（已修）

| 问题 | 根因 | 处理 |
|------|------|------|
| **L2 的 `内心想法` 稳定返回空** | 模型把混合 key `内心想法InnerThought` 写成 `内心想法`，`raw.get(完整名)` 静默取空。**gushi3 的 N45 栽在同一个坑上** | `small_tool.pick_field()` / `canonical_table()`：读取端按"剥掉 ASCII 的归一化名"匹配。gushi3 当年是给单个字段打补丁，这次做成通用的 |
| **L3 写的位置会漂** | 玩家说"往青木山脉走"，L3 自己编了个"落霞坪外山道" | 给 L3 传 `已知地点`（地点树前 3 层，21 条）+ prompt 明确"位置必须复用已知分段、方向必须对" |
| **L3 没有跨轮记忆，旁白前后矛盾** | L3 看不到 NPC 的主观表，也看不到上一轮的旁白，"丹药上一轮明明没给"它不知道 | 给 L3 传 `最近经过`（全局上下文末 10 条） |

#### 阶段 0 的性能数据（顺带拿到，供阶段 1 参考）

| 层 | 次数 | 均耗时 | 输出tok | 推理tok | 推理占比 |
|----|-----|-------|--------|--------|---------|
| L1 | 8 | 23.3s | 37671 | 35141 | **93%** |
| L2 | 24 | 8.9s | 34847 | 25284 | 73% |
| L3 | 8 | 11.9s | 18739 | 17494 | **93%** |
| S1 | 8 | **0.9s** | 187 | 0 | 0% |

- **推理仍是绝对大头（73~93%）**，与 gushi3 的结论一致 → 关推理还是第一杠杆
- **S1 关推理后 0.9 秒返回**，旁路设计验证成功
- **新的耗时大头是 L1（23.3s）**，但它的可见输出只有 ~320 tok/轮——
  **慢在想，不在写**。§八 风险 1 担心的"L1 输出体量"没有出现（写的不多），
  但它想得很多，这属于阶段 1 要处理的事

### 阶段 1：推理消融（单变量）—— ✅ 已完成（每组 3 遍，共 75 轮）

跑法：`python src/test/run_ablation.py --repeat 3`（`G4_THINKING_OFF` 环境变量覆写，配置表不动）。
报告：`src/test/ablation_report.md`（主剧本）＋ `ablation_report_peer.md`（近修为剧本）。
逐轮产物：`src/test/ablation_runs/<组>/rep<N>/round_XXXX/`。

#### 墙钟：3 遍之后数字才可信

第一遍只跑 1 轮时，同配置两遍差 **77%**（181s vs 321s）——被一次 101.7s 的长尾调用主导。
跑到 3 遍，极差收到 **1.1~1.6×**，数字才稳。

| 组 | 配置 | 中位墙钟 | 极差 | 关键路径 | vs 基线 |
|----|------|--------:|-----:|--------:|--------:|
| 基线 | 推理全开 | **192s** | 1.15× | 41.6s | 基准 |
| 实验1 | **只关 L1** | **120s** | 1.22× | 24.6s | **1.7×** |
| 实验2 | 只关 L2 | 169s | 1.62× | 34.6s | 1.2× |
| 实验3 | 只关 L3 | 167s | 1.14× | 33.1s | 1.3× |
| 全关 | — | **40s** | 1.19× | 9.0s | **4.6×** |

**关键路径模型 `L1 + L2最慢 + L3` 被验证**：基线 41.6s × 5 轮 ≈ 208s，实测 192s，吻合。

单层推理成本（中位）：**L1 ≈ 17.5s/轮**、**L3 ≈ 7.1s/轮**、L2 ≈ 6~17s/次（并行）。

⚠️ 注意：第一遍单独跑时算出 L3 均值 **29s**，3 遍之后是 **7.1s**——那个 29s 完全是被一次
101.7s 的长尾拉起来的。**这就是为什么必须看中位数、必须重复。**

#### 但质量指标把结论反转了

粗指标（套路词、越界、交易一致性）在五组里**全部干净**，看不出任何差别。于是加了一条
针对性的：**L1 产出的感知里，有多少表达了"看不透"**（"瞧不出深浅""摸不到底"这类）。

这需要一个**与玩家修为相近**的观察者才有判别力。世界的韩铁柱是炼气初期、玩家炼气中期——
正合适。为此专门写了 `src/test/scenarios/近修为剧本.txt`（把人带到韩家村）。

**韩铁柱看玩家，L1 的感知：**

| 组 | 感知份数 | 含"看不透"式表达 | 占比 | 逐字复述真值 |
|----|--------:|----------------:|-----:|------------:|
| 基线（L1 推理开） | 12 | **11** | **92%** | 0 |
| 只关 L1 | 12 | **7** | **58%** | 1 |

**关掉 L1 的推理，"看不透"率从 92% 掉到 58%。**

对照：用老剧本（唯一在场者是金丹后期的白鹤，**远高于**玩家）跑同一实验，
得到的是"复述真值 29% → 100%"。那个剧本里"照实看穿"本来就正确，
**所以它测不准**——这正是第一轮实验的方法论漏洞。

#### 结论

**L1 的推理是承重的。** 它省得最多（1.7×），但代价是设计枢纽——失真感知——的质量明显下降。

| 层 | 省多少 | 质量代价 | 建议 |
|----|-------|---------|------|
| **L1** | **1.7×** | 失真率 92%→58% | ❌ **不要关** |
| L3 | 1.3× | 未测出（交易一致性 100% 保持） | ⚠️ 可考虑 |
| L2 | 1.2× | 未测出 | ⚠️ 可考虑，但并行、收益最小 |

**"全关 4.6×"这个诱人的数字，代价是废掉整个设计的枢纽。** 所以它不是一条可走的路。

#### 下一步的线索

既然 L1 的推理不能省，那就只能**让它少想**。L1 的耗时代价是 17.5s/轮，
而它的**可见输出只有 ~320 tok/轮**——**慢在想，不在写**。

待验假设：**L1 的长尾是提示词引起的"想太多"，不是任务本身难。**
证据是长尾形状——同一轮其他调用正常，只有一两次飙到 2~9 倍。
如果成立，给提示词加收束条件就能把尾巴压下去，**而不丢推理能力**。

### 阶段 2：层数消融

**在阶段 1 定下来的模型配置下**，测 L1 合并 / 不合并。这时层数的账才算得准。

### 实验协议

**三个必须固定的**：

1. **同一组输入脚本** —— 覆盖：普通对话 / 移动 / **交易** / 战斗 / 无NPC独处。
   **交易那条特别重要**，它专门检验 L3 的客观结算。
2. **同一个存档起点** —— 每轮重跑前读档，避免状态漂移污染对比。
3. **每组至少 3–5 轮** —— **别省这条**。数据显示同一层同一任务的推理量能差 **4 倍**
   （N6：`2485 / 1840 / 596 / 1363 / 934`），跑一轮的结论就是噪声。

**记录**：耗时 + token（`LLMClient` 已加好日志）+ 下面的质量评分。

### 质量怎么看

不能只看"感觉好点没"。对着设计原则查三条，按重要性排序：

| # | 检查项 | 为什么它最脆弱 |
|---|--------|--------------|
| **1** | **NPC 有没有说出它不该知道的** | 信息隔离是这个系统的核心。非推理模型更容易"顺手"用上它没感知到的信息。**这条最关键** |
| **2** | **回应有没有套路化** | 关掉推理后模型更容易复读（"深不可测""蝼蚁"刷屏），失真感知会退化成模板 |
| **3** | **状态变更自不自洽** | 交易、伤害、物品转移对不对得上。检验 L3 |

**第 1 条可以半自动化**：把 L2 收到的失真感知存一份，跑完比对 NPC 对白里有没有出现感知之外的信息。
值得写——人工查很容易漏。

### 剩余风险（实验之外的）

| # | 风险 | 怎么验 |
|---|------|--------|
| 1 | **L1 输出体量** | 一次为 K 个 NPC 各写一份失真感知，输出变长 → **直接增加输出 token，而输出是延迟主因**。这个风险因 token 数据而**加重**了。跑对照：N2+N3 分两次 vs L1 一次产出 N 份 |
| 2 | 记忆巩固的副作用 | 摘要可能丢关键细节。后台任务，可回退 |
| 3 | 关推理后数值乱来 | 见 §3.5：数值一律夹取，且失败回落规则兜底 |

## 九、总结

| | gushi3 现在 | gushi4 | 状态 |
|--|-----------|--------|------|
| **延迟主因** | 推理 token 占 85% | **关思考，预期 5x** | 待阶段 1 验证 |
| 关键路径 LLM 跳数 | 4 | 3 | **待阶段 2 验证** |
| 每 NPC 串行链 | 2 | **1** | 结构性，确定 |
| 结算域暴露面 | K 次/轮 | **1 次/轮** | 结构性，确定 |
| 感知精细度 | 全局一次（粗） | **每 NPC 一份失真感知**（不增加调用） | 待阶段 0 验证质量 |
| 结算层的输入 | 11 表/NPC | **2 表/NPC** | 结构性，确定（**但不提速**） |
| 结算层的输出 | 6 表增量 | **2 表增量** | 结构性，确定（**但不提速**） |
| 客观状态一致性 | 单方视角，交易会出洞 | **L3 唯一写入口，双方一起变或一起不变** | 拆 L2/L3 的**唯一理由** |
| NPC 表上限 | 只截 3 张 | 全部截，配置化 | 防增长，**不是提速手段** |
| 简单判断 | 混在大模型调用里 | 旁路，不占跳数 | 确定 |

**一句话**：这次真正的收获不是"减了几层"，而是**搞清楚了延迟来自哪里**——
来自模型"想"，不来自层数，也不来自喂了多少数据。层数问题要等关掉思考之后才浮上来。
