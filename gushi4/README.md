# gushi4

LLM 驱动的多 NPC 交互式叙事引擎。**设计依据见 [设计方案.md](设计方案.md)** ——
那份文档写的是"为什么这样做"，这份写的是"怎么跑起来"。

## 快速开始

**用启动器**（推荐）：

```bash
cd <项目根>
python start.py                 # 网页版，会自动开浏览器
python start.py term            # 终端版
python start.py test            # 跑离线测试，不花 API 额度
python start.py web 9000        # 网页版，指定端口
```

Windows 上**双击 `start.bat`** 等价于 `python start.py`。

> `start.bat` 里**一个非 ASCII 字符都不能有**。cmd.exe 按当前代码页逐字节解析批处理
> 文件，UTF-8 中文在这里会被解析错乱——注释行会被当成命令执行（踩过一次）。
> 它现在只做一件事：找一个能用的解释器（`py -3` → `python` → 官方安装器的默认路径），
> 然后把活全交给 `start.py`。**优先用 `py`**，因为 `py.exe` 在 `C:\Windows` 里，
> 即使 Python 本体从没加进 PATH 它也在。

启动器会自己检查 Python 版本、API key、缺的依赖并现装。**它写成了 Python 而不是
`.bat`/`.sh`**：cmd.exe 按当前代码页逐字节解析批处理文件，`chcp` 一改代码页，
后面含中文的行就会解析错乱（实测把参数判断搞坏过）；要同时覆盖
cmd / PowerShell / Git Bash 三种编码环境，写两遍还都不稳。Python 是进程，编码自己说了算。

> 前置：Python 3.10+、`DEEPSEEK_API_KEY`（或 `MODELSCOPE_API_KEY`）。
> 依赖 `requests` + `flask`，缺了启动器会装。

**手动跑**（想直接控制参数时）：

```bash
python main.py                  # 终端版
python web/server.py --port 8765 # 网页版
```

**两个前端挂在同一个 `GameEngine` 上**（`common/engine.py`），共用一份流水线，
所以同样的输入得到同样的叙事，不会各改各的漂移。

切换世界观改 `common/base_cnf.py` 里的 `WORLD_DATA_SELECT`。

> Windows 终端若报编码错（`UnicodeEncodeError: 'gbk' codec...`），前面加
> `PYTHONIOENCODING=utf-8`。启动器已经处理了这件事，手动跑才需要。

## 一轮的调用链

```
N0 消费后台产出 + 显示场景
N1 读输入 + 命令
── 快照（供 !! 回滚）──
L1 感知过滤                  ← 判断权都在它身上了（开推理）
L2 角色层（每 NPC 一次，并行） ← 关键路径第 2 跳
R1 节点传播（纯规则）
R4 机缘导演（纯规则，按出发地掷骰）→ 结果进 L3 输入
L3 结算层                    ← 关键路径第 3 跳
R2 推进时钟（纯规则，耗时由 L3 判断）
心跳触发（后台线程，立即返回）
```

**关键路径 LLM 跳数 3**（gushi3 是 4）。⚠️ 这是**假设不是结论**——
按设计方案 §八，阶段 2 才用实验定。**阶段 0 不测性能。**

### 引擎与前端分离

上面的循环体在 `common/engine.py` 的 `GameEngine` 里，**不在 `main.py`**。

`main.py` 现在只剩"读键盘 + 把事件画到终端"，`web/server.py` 也只做"收 HTTP + 推 SSE"。
两边调同一个 `run_round()`。

**引擎自己从不调用 `input()`**：

| 阻塞点在终端哪里 | 网页怎么替代 |
|------------------|-------------|
| `main.py` 的 `input('>')` | 玩家输入由 `POST /api/input` 传进 `run_round()` |

**移动也不再需要前端先选目标**（2026-10-08）：位置由 L3 出 `去向`（地名）+ `行程`（语义进度，
`刚上路/半路/将到/到了`），代码按**整段路程的几分之几**把坐标落在某条路的路径线上。
所以 `{移动}` 标记、终端位置菜单、`/api/move`、引擎里那段移动兜底**全部退役**
——「走得到就到，走不到就到路上」从 2026-10-08 起是真的。详见下面「位置：坐标是真源」。

### 事件流

所有输出统一成 `_emit(event)`，终端渲染器和 SSE 渲染器是**同一接口的两个实现**：

| type | 内容 |
|------|------|
| `scene` | N0 的场景（位置/在场/时钟） |
| `stage` | 阶段进度（`start` / `tick` 每 0.4s / `end` 带耗时） |
| `dialogue` | L2 各 NPC 的回应 |
| `narration` | L3 旁白 |
| `dim` `info` `error` | 幕后简讯 / 命令回显 / 异常 |
| `time` | 时钟推进 |
| `round_start` `round_done` | 回合边界 |

`GameController` 也挂了个 `on_output(kind, text)` 接收器接到 `_emit` 上。
**用 sink 而不是"把 print 改成返回行列表"**，是因为 `_do_save` / `_save_worker`
是在**后台线程**里输出的（`💾 已存档`），返回值送不回调用方。

`Stage` 的 `on_event` 是**叠加**不是替换：终端有 TTY 时照常重绘那行 `⟳`，
网页同时收到 tick。做成互斥的话，网页模式下终端渲染就被关掉了。

## 三个信息域（整个设计的枢纽）

| 信息域 | 谁 | 看得到什么 | 能写什么 |
|--------|-----|-----------|---------|
| **世界域** | L1 | 事件 · 全员名册（名字+真实实力） · 玩家真值 · 幕后情报 | 失真感知 · 事件边界 · scope |
| **角色域** | L2 / B2 | **一个** NPC 的 11 张表 + **它自己那份**失真感知 | 8 张**主观**表 + 对白 + 意图 |
| **结算域** | L3 | 玩家**全量**实况 + 各 NPC 的**客观侧（2表）** + 所有意图 | 2 张**客观**表 + 旁白 + 耗时 |

**边界依据是「信息性质」，不是「实体是谁」**：

- 主观（记忆·信念·好感度·待解释…）→ 只有本人视角该碰
- 客观（持有物·位置·伤势）→ 跨实体，必须上帝视角

这条边界由**代码强制**，不靠 LLM 自觉：

```python
L2.sanitize_npc_delta()      # 只放行 8 张主观表，客观表写了也丢
L3.sanitize_objective_delta() # 只放行 2 张客观表，主观表写了也丢
```

### 为什么 L3 是唯一的客观写入口

**物品转移、战斗伤害、位置变化本质上是跨实体的**，从任何单方视角看都不完整。

玩家说"我给一百灵石，你把剑给我"——L2 看不到玩家的钱包，只能信。
要是 L2 擅自把剑扣了，L3 事后发现玩家付不起，**剑已经出去了，没人能收回来**。

所以 L2 只出 **`动作意图`**（"我打算给他"），L3 同时看到双方持有物，
判定成立与否，**双方一起变或一起不变**。

交易破裂时 L3 注入一条 `破裂观察`（事实记录），NPC 的反应**下一轮**由 L2 自然发生——
复用「观察 → 感知」通道，零新机制。

## 失真感知（越级战斗的来源）

NPC 该知道玩家多少？**不是"给或不给"，而是"每个观察者持有一份失真的认知"。**

| 观察者 | 看到的"玩家实力" |
|--------|----------------|
| 低阶看高阶 | "气息深沉，看不透深浅" |
| 高阶看低阶 | "根基浅薄，连内门都够不上" |
| 同级 | "与我相仿，胜负难料" |

**不给刻度**。不告诉 LLM "等级差大于 X 就看不透"——给了就变成可反推的公式，
玩家能算出实力对比，越级战斗就不存在了。

因此 L1 **持有玩家真值**（不知道真值就没法失真），但**输出里只有失真后的版本**。
代码会检查真值有没有被逐字复述，复述了就记警告（不硬拦——高阶修士看穿低阶是**正确**的失真）。

## 网页界面（`web/`）

纯原生 HTML/CSS/JS，**无构建步骤、无 npm**。单页，打开就玩。

| 区域 | 内容 |
|------|------|
| 顶栏 | 名字 · 当前位置 · 游戏时间 · 轮次 · 面板/预设/撤回 |
| 左栏 | 状态 · 身体 · 持有物 · 在场 |
| 中间 | 阶段进度条 + 叙事流 + 输入框 |
| 右栏 | 地点树 · 全部 NPC · NPC 内部表 · 三种上下文 · 层耗时 |

### 面板可自由开关

每个面板是一个独立组件（`app.js` 的 `PANELS` 注册表），勾选即显示，存 `localStorage`。
两套预设一键切：**游玩**（只留状态与叙事）／**开发**（全开）。

开发预设里的 **NPC 内部表**能点开任一 NPC 看它的 11 张表（观察/待解释事件/好感度/记忆…），
标着「玩家不可见」——调 NPC 行为时不用再去翻 JSON。

### 地点：小地图（地图是主路径）

> 📖 **术语（2026-10-10 起统一，定义在 `地图格式.md` §1.0）**：
> **地图 = 节点 + 路段**。节点由**内部属性**（`类型`）分成 **地点**（能停留的点）与
> **地区**（一块面，由 `范围` 画出：只有圈、不当路段的端点）；
> **路段**＝两节点之间的通路，**路段属性**是它自己的（`双向=`、`| 说明`…），
> **段属性**说的是**途经**（内部那几段地形）。
> 本节与别处**历史段落**里的 **"地块" = 节点**、**"区域/面" = 地区**、
> **"地段" = 节点**——都是旧词，含义不变；
> **代码还没跟着改**（`地点` 关键字、`地块` 键、`is_region`、`当前地段` 都还是旧名）。

**地图怎么画**（2026-10-10 落地，判据是作者写的 `类型`，不是"有没有子节点"）：
**地点**画成一个**实心盘**，盘的半径**就是它的 `范围`**（不再另画一圈——点了那个盘和
"那个地方有多大"是同一件事）；**地区**把 `范围` 画成**虚线圈**、**不画点**，名字落在圈心。
点击热区跟着同一个半径走，所以"看得见的那块"永远点得中。

**真文件里的地区**（同一轮补的）：苍云大陆 / 东域 / 西域 / 南域 / 北域 / 中州 写上了 `类型`。
`去向` 给地区名时（"我去东域"），代码落到**它子树里离你最近的那个地点**——地区的坐标只是
那个圈的圆心，不是落脚点。

`GET /api/map` 给两样**分开的**东西——静态层（节点 / 路段 / 范围的几何，一局只算一次）
与动态层（当前坐标，每轮都动）。前端把它们画成同一张 SVG 的两组，
SSE 只重画后者。几何的真是 `data/B1_worldState/世界.map` 里的 `坐标` / `范围` / `路径线`。

**手改几何文本 = 作废那一格"拖过的数字"**（`edDropGeoOverride`，2026-10-10）：拖动把数值记进
`S.edit.geo`，而它优先于文本（预览与落盘都先应用它）——不作废就是"改了没反应"。
改了地块的坐标时，连着它的那些路的 `路径线` 覆盖也一并作废，交回服务端的"端点跟着地块走"。

**地块与线：按"谁离指针近"判，且线要"基本压在指针上"才抢得过地块**（`mapPickPlace` /
`mapPickRoad`，2026-10-10 修）。判据是三个条件的合取（线离指针 ≤6px **且** 指针没压在
某个点上（离点 >3px）**且** 线更近），少一个都会被反例打脸：命中圈互相盖住（谁后画谁在上面）、
线的端点就是地块的坐标、名字离自己的点比路还远。

**地图上点地块会把页签切回「地块」**（同一天修）：以前在「路」页签下点地图上的地块，
选中的是 `路[i]` —— 检视器显示**另一条路**、地图高亮也是那条路的曲线。用户的原话
是"先点万象洞天，拖完那条路的曲线，再点其他的就 bug"。

**点地块按"离指针最近"判**，不按"画在最上面"判（`mapPickPlace`，2026-10-10 修）：
命中圈的半径**当时**是屏幕恒定 15px，密集处会互相盖住，而 SVG 里谁后画谁在上面——
于是"点 A 选中 B"（实测 41 块里 3 块）；📍 标记又压在玩家所在地、邻居的名字标签
也会盖住别人的点（另有 4 块**点了没反应**）。现在按距离判，这两类都没了。
**同日晚些时候又把半径收窄了**（摆图时实测）：15px 比天道宗院里 7 个点的间距
（未缩放时 15 个屏幕像素）还大，谁都抢得过谁——改成**跟着那个点自己的屏幕半径走**
（`mapReachPx`：+4px、下限 6px）。恒定屏幕像素的只有**字**；热区恒定是错的。

**点地块＝选中，再点「前往」才出发**（2026-10-08 改）。原先是点即前往，
但 41 个地块挤在一张图上，误点一下就是一次真实回合（花额度、推进世界）——
让"要去哪"和"去了"分成两步，成本才看得见。出发走 `POST /api/input`
这**同一个**入口，合成一句"我往X去"——去哪由 L3 判、坐标由代码落
（见 `地图实施计划.md` 阶段 1A）。没有 `/api/move` 这种接口，那条路已退役。

**可缩放**：滚轮以指针为锚点缩放、按住拖动平移，`＋ / － / ⟲` 按钮，`⤢` 进全屏。
右栏宽度可拖（拖拽条，存 `localStorage`）。

**标签不是"全显/全隐"两档，是逐个避让摆放的**（`applyMapLabels`）：一个名字只在
「不跟已经放下的名字相交」时才显示，优先级是 **当前/选中 → 目的地名 → 区域名 → 叶子名**，
而且这个优先级**随缩放翻转**——缩着看格局（区域名赢），放大看细节（叶子名赢）。
于是"放大 = 名字一个个冒出来"，而不是跳档。

两个把这条做对的关键（都踩过）：
- **字号必须是屏幕恒定像素**（`--mlabel`，由 JS 按缩放反算）。写成画布单位时，
  缩放会把**文字和几何一起**放大 → 重叠跟缩放无关，**放大再多次也分不开**。
- **换算只能有一个 scale**：`preserveAspectRatio="meet"` 是等比缩放 + 居中留白，
  x/y 各算各的会让标签在一个**被拉扁的坐标系**里互相避让（全屏浮层写死高度时就中招，
  1145px 宽反而只放下 10 个名字）。同理，全屏地图不能写死高度。

没几何时降级回旧折叠树（`panelTreeFallback`），但树**不再是主路径**。

### 世界编辑器（`✎ 编辑`）

地点面板右上角的 `✎ 编辑` 打开**全屏浮层**：左边那张图就是上面这小地图的**同一个组件**
（同一个 `buildMapStatic`），只是放大、点＝选中；右边是实体列表 + 字段检视器。

- `GET /api/map/edit` 给**扁平表单**；`POST /api/map/save` 收回去。
- **图跟着表单走**：`POST /api/map/preview` **只看不写**，拿手上这份表单走
  **保存那条流水线**（`map_io.prepare_edit`）重算一遍图。少了它，
  编辑器左边那张图只是"开编辑器时拍的快照"——删掉的路还画在上面，
  **看得见、点不动、也删不掉**（用户报的"幽灵线"）。规则只留 Python 那一份，
  前端不抄级联；预览失败就留着上一张图并说话。
- 字段值**就用 `.map` 的语法**：`[a,b]`=列表、`是`/`否`=布尔、纯数字=数字，其余是文本。
  键名不限——"字段不定，交由 LLM 判断"就是这么落的。
- **写盘三查**（校验 → 往返自检 → 备份），任一不过**一个字节都不写**。
- **改名/删除会级联**（`map_io.cascade`）：改名会一起改子地块的 `属于`、路的 `从/到`、
  几何的键；删地块会清掉它的 `坐标`/`范围`，端点没了的连带删路，**子地块挂到爷层**
  （删 天道宗 ≠ 删它下面 7 个地方）。**改了什么一律列在返回里**，不悄悄做。
- **`| 说明` 四个位置都活了**：地块（叫 `描述`）、**路、段**——解析 / emit / 表单 /
  编辑器四个地方都通。以前路的那一段是**解析进来就扔**，手工写上去的一句话保存一次就没了
  （写盘三查也拦不住：模型里从头就没有它）。
- **打开编辑器时会提醒"键写歪了"**（`map_io.key_notices`，**不拦保存**）：像保留键的
  （`类形`≈`类型`）、保留键写在没人读的位置的（`描述=` 写成键——引擎只认行尾 `|`）、
  以及**值是一个已知地点名的**（`上级=东域`，这条专治编辑距离抓不到的同义词）。
- **区域不画点**（`类型=大陆/区域/域/州`）：区域是"面"，图上只画它的范围圈——
  给一个点就等于说"这儿是个可以去的地方"（"去东域"＝去一个放射中心）。
  圈、名字、命中区照旧，所以它照样点得中、选得中；**站在旷野上也不会被说成"就在最近那个村子里"**
  （`（在东域的旷野上）` + `不在任何地点`）。机制在了，**数据等修订地图那一次补**（见 `地图格式.md` §9.1）。
- **`行程` 报**段名**也认**（"走到雪岭了"）：折算成整段路程的 frac——**先接这条再铺段数据**，
  不然 L3 越照着段名说、越容易被 `frac=1.0` 一步送到目的地。
- **在路上时 L3 看得到路的属性，也看得到"正在穿过哪一段"**：`当前节点` 的第一条是
  `（在路上）A → B` + 路的 `地形`/`隔阻`/`凡人脚程`，第二条是 `（正在穿过）雪岭段` + 段的属性
  （`海拔=8000`、`隔阻=需御寒`）——那是判"能不能过、几时到"的依据。
  这两样以前**都没有**：路的属性因为读错了形状恒为空字典（见 `地图格式.md` §3.1 的注），
  段更是连名字都没进过 L3。
- 保存后 `gc.reload_world()` 热重载，但**不再说"已保存并热重载"那一句话**——
  它按三类分：**立即生效**（地点/路/几何/`NPC_上限_*`）· **需重启**
  （`玩家初始数据`、`游戏开始时间`、`时间格式`）· **一直成立的那条**：
  改 `产出` 或节点属性**不会重算场上 NPC 已有的记忆**。
- **几何也能拖**（阶段 3）：编辑器左图上**拖地块点＝改 `坐标`**、**拖控制点＝改 `路径线`**
  （选中一条路才出控制点）。拖动过程**只改数字**，松手记进 `S.edit.geo`，
  保存时由服务端 `map_io.apply_geo_patch` **生成文本**——
  前端不拼字符串，因为 `.map` 的坐标写法是 Python 的 `repr(float)`
  （`170.0` 写成 `170` 就变成 int 了），在 JS 里再抄一份格式化规则就是两处真相。
- **拖一个地块，连着它的路那一端会跟着走**（线的两端本来就**是**那两个地块，
  不跟线就从空地开始）——这是派生改动，所以**会列在回执里**，不悄悄做。
- **「＋ 新建」**：新建地块会自动补 `坐标`（落在视野中心）与 `范围 圆(16)`
  （没有范围 `locate()` 认不到它，站上去只会是"在路上"）；新建路会给一条直线路径，
  要弯自己拖控制点。名字是占位的（`新地块1`），**存之前先改掉**
  （改名会连带改引用；连"新建完就改名、中间没存过"那种也认得出——
  靠几何的键补一次配对，否则新地块的 `坐标` 会被当成悬空几何清掉）。
- 硬指标：**改一条属性 → `git diff` 只有那一行**。新增字段只把那行加长，不动别处。
  为此服务端 `app.json.sort_keys = False`（Flask 默认按键排序，一排序就是满屏 diff）
  且落盘前 `canonicalize` 按盘上顺序对齐键序（改名也留在原位，不甩到末尾），
  最后 `order_places_dfs` 把地块列表排成 **DFS 前序**——不然新建的**子**地块
  会被追加到文件末尾，而它其实该出现在中间（往返自检会拦下）。
- 备份落在 `data/B1_worldState/_备份/`（**不进版本库**；历史上每一版交给 git）。
- **将来会整张重画地图**（现在的连线/位置/范围只是让引擎跑起来的脚手架）。**不需要改代码**：
  `--drop-roads --drop-geo`（清掉路与几何，地点与 `配置` 原样留着）→ `--skeleton`（铺骨架路草稿）
  → `--layout`（铺坐标/范围）→ 编辑器里拖。**一次只跑一条命令，每条都会先自动备份**。
  ⚠️ 重置前先 `git add` 一次 `世界.map`（它没进版本库）；别在编辑器里点 40 次「＋新建」；
  也别指望 `--layout` 的坐标在地理上是对的（它是画图初值）。详见 `地图格式.md` §10。

细节与代价见 `地图格式.md` §5.1、`地图实施计划.md` 阶段 2。

### SSE 用一条常驻通道

页面加载时开一条 `/api/stream` 并保持，`POST /api/input` 只负责触发回合。

每轮开一条新连接的话，`POST` 和 `GET` 的到达顺序就成了竞态——
回合可能在 SSE 建立**之前**就开始跑，前几个事件直接丢掉。

### 并发

- **写**：`run_round()` 全程持锁，一轮一次。
- **读**：只读接口**不加锁**。写回路径是整体重绑定而非原地改
  （`new = deepcopy(...); self.player.player_dict = new`），CPython 下单次属性赋值原子，
  读者读不到半个。组装视图前先浅拷贝——遍历 dict 期间被改动会抛 `RuntimeError`。
  代价是轮次进行中可能读到跨层混合快照，这是固有的，不是 bug。

### 只监听 127.0.0.1

没有认证、没有多用户。绑 `0.0.0.0` 等于把整个游戏状态（含所有 NPC 记忆和存档）开放给局域网。
要远程访问得先加认证。

## 生命值体系：数值 / 文本 可切

全库**没有** `生命/血量/HP` 这类字段——受伤原本只是一句自由文本（`体力状态`）。

但**有数值更像游戏，没数值更像小说，能两者切换本身就是这个引擎的优势**：
它既能往游戏引擎迁移，也能停在一个多人小说演化器上。

所以数值**不硬编码**，由世界配置 `生命值体系` 决定：

```jsonc
// data/B1_worldState/世界.map 的 `配置` 行
"生命值体系": "数值"   // → L3 追加条款，维护 生命/灵力 两个 0-100 整数
                      //   "文本" → 不追加，退回原样（只有文字状态行）
```

实现是 `L3_settlement._health_clause()` 往 system prompt **末尾追加**一段，
不走 `load_prompt` 的占位符机制（那是给 `data/prompt/*_custom/` 注入用的，混在一起会打架）。

前端**按字段存在与否自适应**：拿到数字就画条，拿不到就退回文字行。不猜、不造数。

> ⚠️ 条款里**没有**任何"数值低于 X 就不能如何"的判定规则，并且明确写了禁止。
> 数值只记录**结果**，不参与叙事判断——**越级战斗必须始终可能**，
> 这条不能因为加了数值就退化。

## 节点功能：地点是"动词"

`世界地点列表` 里**每一层级**的节点都可以带 `_属性`，不只叶节点：

```jsonc
"东域": {
  "_属性": { "灵气": "浓郁", "危险": "低", "势力": ["天道宗", "星辰阁"] },
  "外门弟子修炼区·落霞坪": {
    "_属性": { "功能": ["修炼", "比试"], "危险": "极低" },
    "描述": "炼气期外门弟子日常修炼之所"
  }
}
```

**老写法仍然合法**——叶节点直接写字符串，就等于"只有描述、没有属性"。
现有地点数据不必重写；缺的属性由 LLM 按世界观现场判断（"交由 LLM 判断就注定
灵活性足够高"）。

保留键是 **`_` 前缀的键**与 **`描述`**（中文地名不会撞上）。所有遍历器都走
`B1WorldLayer.normalize_node()` 这**一个**归一化点：

> ⚠️ 少改一处，`_属性` 就会变成一个叫"_属性"的地点混进路径，L3 拿到它之后
> **完全可能把玩家的位置写成 `苍云大陆·东域·_属性`**——位置一漂，之后所有
> 距离计算都跟着漂，**且不会报任何错**。`src/test/location_test.py` 专门盯这条。

属性被谁消费：**L1**（判断"谁听得到"——坊市里喊 ≠ 洞府里喊）、
**L3**（旁白质感、此地行为是否自然）、**R4 机缘导演**（`_属性.产出`，见下节）、
**网页地点树**（当前节点下方那排标签）。

> ⚠️ 属性是**描述不是规则**。"危险=高"**不等于**"某人一定受伤"——
> 那类公式正是本设计禁止的东西。属性只帮 LLM 把世界写对，不替它裁决。

`_属性.产出` 是**该地能得到什么**及其概率（如 `{"物品":"灵草","概率":0.25}`），
由 `common/R4_opportunity.py` 掷骰；**概率不进前端**——把投放率露给玩家等于把骰子给他看。

## 位置：坐标是真源，路径是派生

**位置存坐标**（`当前状态CurrentState.位置 = [x, y]`）。这解决了一整类问题——

> 在那之前，位置是**模型写的自由文本**。实测出过一次事故：玩家"一路往青木山脉方向走去，
> 赶了三天的路"，L3 把位置写成 `苍云大陆·东域·青木山脉方向（离天道宗三日脚程）`。
> 这个字符串**谁也解析不了**，于是当轮**所有节点能力一起失效**（灵气、产出、规矩全读不到），
> 而且**不报任何错**；下一轮它就在"拿不到属性"的状态下，把 `灵气：浓郁` 的青木山脉
> 叙述成了「灵气**偏薄**」。

改法的关键是**把"表示的笔"从 LLM 手里收回来**（原则 1/2：状态的表示归 Python，判断才归 LLM）：

| | 谁 | 怎么走 |
|---|---|---|
| **去哪** | L3 | 输出顶层字段 `去向`：**地名**（必须来自"已知地点"），没动就 `""` |
| **落坐标** | 代码 | `GameController.set_position()` —— **位置的唯一写入点** |
| **反查地块** | 代码 | `B1WorldLayer.locate(x,y)`：落在哪个范围内（嵌套时取最深） |

几条硬规矩：

- L3 想写 `位置` / `当前所处位置` 会被**直接丢弃**（`sanitize_objective_delta` 里硬丢，并记警告）
- `去向` 解析不出 → **原地不动**（宁可不动，也不要一个编出来的位置）
- `当前所处位置`（路径）**降级为派生缓存**：由 `set_position` 顺手写，好让引擎里十几处
  读"路径"的地方一行都不用改；`ui_test` 有一条断言盯着两者一致，防止它们各说各话
- **几何只用于客观判定**（他在哪、在不在场、前端怎么画）；听不听得见 / 传多远 / 走多久
  仍然全归 LLM

「在路上」不是另存的字段——它就是"坐标不落在任何范围里"这个事实（`locate()` 会退到最近的地块）。

## 机缘导演：世界真的会给东西

在它之前，世界**不会给玩家任何东西**。玩家能拿到物品的唯一方式是对话里被 NPC
"给"——那是小说逻辑，不是游戏逻辑。而 `_属性` 里那 15 张 `产出` 概率表
（灵虚集的低阶丹药、青木山脉的灵草、万蛇谷的蛇王内丹…）写得很完整，却没有代码读它。

`common/R4_opportunity.py` 就是那个消费方。**纯规则、零 LLM、不写任何状态。**

### 三条边界（不是实现细节，是设计约束）

| 约束 | 它怎么守 |
|------|---------|
| **骰子只管"有没有"，LLM 管"是什么样"**（原则 8） | Python 只掷骰，产出 `{物品, 条件}`；怎么被发现、谁拿到、写成什么句子，全在 L3 |
| **客观状态只有 L3 能写**（D5/D12） | R4 **一个字都不写**。结果只进 L3 的输入，由 L3 走 `sanitize_objective_delta` 落到 `持有物Inventory` |
| **概率不给玩家看见** | 概率**读完就丢**——`roll()` 的产出里没有这个键，不进 L3 输入、不进日志正文、不进前端 |

「世界不会主动给东西」和「R4 不写状态」是同一条线的两端：**掷骰与兑现被分开**，
所以交易一致性那套（双方一起变或一起不变）完全不受影响。

### 触发：时间门，不是玩家动作

    距上次掷骰 ≥ 机缘_间隔_小时  且  今日得手件数 < 机缘_每日上限

> ⚠️ **默认值 0.5 小时是按实测定的，不是拍脑袋**（2026-10-08，真实 API）：
> L3 对普通一轮的耗时判断是**分钟级**——"转了一圈" +6 分、"逛了大半天" +3 分、
> 当街拔剑 +3 分；只有显式时间跨度才给小时以上（"赶了三天的路" +4320 分）。
> 而一个游戏日是 1440 分，所以间隔取 6 小时等于 **60~100 轮才有一次机会**，功能被埋掉。
> **反向结论**：也正因为一轮才几分钟，`机缘_每日上限` 几乎永远不触发——
> 真正决定投放频率的是这个间隔，上限只在长时间跨度（闭关/赶路）时才起作用。

- **只在玩家出发地掷骰**（用 `loc_before`，不是移动后的位置）。错过就错过。
- **中与不中都消耗窗口**。否则站在青木山脉反复空掷直到命中，等于把 `概率`
  变成"每次都能拿到"，只是多等几轮。
- **每日上限按件数算**，不是按次数——产出表是**逐条独立判定**的（概率不归一），
  青木山脉四条全中会一次出四件，按次数算上限形同虚设。
- **首次调用只记时间、不掷骰**：读档后本层是新建的、计时归零而时钟是存档里的大值，
  不设这道闸就会"一读档立刻爆一次机缘"。（后台心跳那个 `_last_trigger_elapsed`
  有这个毛病，R4 不重复它。）

#### 为什么不做成"玩家说采药 → 掷骰"

直觉上更省的方案。但**判断"这句话是不是一次采集尝试"本身就是语义判断**，
纯规则做不了，只能再加一次 LLM 调用——那正是 S1 旁路被摘除的原因
（"旁路绝不能成为新的故障点"，见 `common/R2_time.py`）。

所以改成时间门，骰子在玩家什么都没说的时候也照掷——**世界不围绕玩家转**，
和 B1a 是同一条原则（"他不参与的事照样在发生"）。玩家能拿到的只是"恰好在场"的那一份。

### `条件` 是硬门槛，由 L3 判

产出条目可以带 `条件`（"深入山脉腹地" / "需破开血月光门" / "需先胜过金丹期蛇王"），
是**自由文本、无 schema**。R4 只负责原样搬运，**判断是否满足的是 L3**——
和"节点属性是描述不是规则"是同一条。不满足就**不得落地**，只能旁白如实交代。

条款（`L3_settlement._OPPORTUNITY_CLAUSE`）**只在真的掷出东西时才追加**，
和 `_health_clause()` 同一个姿态：没机缘的轮次不为一段用不上的规则付 token，
输入里的字段与 system prompt 里的说明也因此始终成对。

### 离线能验到什么

`src/test/opportunity_test.py`（61 项）把三层都钉住了：表定位与清洗、
节流与上限、以及**假 LLM 跑一整轮**验"机缘确实进了 L3 输入 + 条款只在该出现时出现 +
R4 自己确实没写状态"。真实的 LLM 怎么用它，要靠 `run_scenario.py` 那一轮看。

### 谁听得到：判断权在 LLM，Python 只做管道

**Python 不判断"谁听得到"。** 这件事的判断权完整地在 L1 手里：

    L1  → 感知分发{名: 失真内容}   谁听到了什么
    L1  → 节点传播{消息, 传到}     传闻传给了谁

R1 / R3 退化成**执行层与校验层**，只做三件不涉及叙事的事：

| 层 | 还做什么 | 不做什么了 |
|----|---------|-----------|
| **R3** | 名字防幻觉 · 执行 `hidden` 声明 · `involved` 漏感知补齐 | ~~按 scope + 段数算谁有权感知~~（`_allowed_set` 已删） |
| **R1** | 名字防幻觉 · 排除已亲身经历者 · 写进观察表 | ~~`path[:level]` 祖先前缀展开~~ · ~~`mask` 概率抽签~~ |
| **L2** | —— | 拿到的「对话上下文」**不含本轮玩家原话** |

#### 为什么删掉 R3 的距离过滤

原来的模型是「感知范围 = 距玩家 N 段以内」+「scope 枚举」。**两个假设都不成立**：

| 段数模型的假设 | 现实 |
|---------------|------|
| 范围 = 距玩家 N 段以内 | 修仙世界里修为高的人一声长啸能传到**相邻节点**——相邻是**兄弟节点**，前缀/段数模型够不着 |
| 同一节点内机会均等 | 都市里隔一堵墙就听不见 |

而 L1 **本来就在 `感知分发` 里回答了这个问题**。R3 再算一遍，
是在给 LLM 的答案做**二次猜疑**——用一个错误的模型。

#### 为什么删掉 R1 的 level/mask

`path[:level]` 是**祖先前缀展开**：只能覆盖"我祖先链上的子树"，而且每一级**全有或全无**——
没法表达"传到天道宗和坊市、但没传到星辰阁"。`mask` 则是均匀概率，同样假设了"人人等可能听到"。

根子是同一个毛病：**让 LLM 吐一个数字，再由 Python 用一张表把数字翻译成结论。**
数字太窄，表就是那堵墙。而传播范围恰恰是没法用几十个键值对描述的东西——
节点大小、距离远近、修为高低、建筑隔音、深夜还是闹市、当时街上有没有人。

改成 L1 直接给名单后，`消息` 本身也变丰富了。实测一条：

    玩家叶尘在落霞坪长啸一声，声浪传过外门修炼区，却没有撼动护山大阵半分
    → 传到：陈守贵（膳食房）、柳明溪（演武场）——都在 2 段外

旧 schema 里 `msg` 只是静态字符串，`mask: 0.3` 这个数字**承载不了**"却没有撼动护山大阵半分"
这层语义。

⚠️ **旧 schema 不静默兜底。** 如果 L1 又输出 `level`/`mask`，R1 会打一条 WARN 并且不产生传闻——
让 schema 失效可见，而不是悄悄退回旧行为。

#### `scope` 现在是什么

`scope` **不再参与过滤**，只剩两个作用：R3 执行 `hidden` 声明；以及给日志/UI 做描述。

所以「L1 把悄悄话判成了 area」这件事，**不再导致旁观者收到东西**——只要 L1 没给他们写感知。
判断力的真正位置因此从"scope 标签"移到了"**该给谁写感知**"。实测：

| L1 配置 | 悄悄话的感知分发人数 |
|---------|-------------------|
| 关推理 | `[(0人,2次), (1人,2次), (3人,1次)]` ← 有空转，也有一次给了 3 个人 |
| 开推理 | `[(1人,5次)]` ← 稳定 |

代价：L1 单次 1.5s → 5.4s，在关键路径上，**每轮 +3.9 秒**。

> 📌 **一个被推翻的假设。** 我曾推测"L1 关着推理是它判不准 scope 的原因"。
> `src/test/diag_l1_thinking.py` 的对照实验证明**不成立**：开推理后悄悄话的
> `private` 从 1/5 变成 **0/5**——反而更差。推理预算买不来 scope 准确性，
> 它买来的是**感知分发的稳定性**。

### 多久：移动耗时也交回 LLM

同一个毛病，同一处修法。R2 原来自己算：

    移动分钟 = 声明分钟
             | 段数 × 移动耗时_每段分钟 ÷ 移动方式倍数

`段数 × 每段分钟` 把距离简化成"差几层节点"；`移动方式倍数` 是张要穷举近义写法的表
（步行 1.0 / 骑马 4 / 御剑 20…），补不到就静默按步行算。

**现在 `本轮耗时分钟` 的语义改成「原地活动 + 赶路」**，由 L3 一起判断——
L3 本来就决定玩家这一轮去哪，正好一起给时间。R2 只剩 `clamp` + `game_clock.advance()`。

`S1_quick_judge.py` **随之退役**（它全部职责就是产那个倍数）。文件保留备查，
标注了退役原因和"什么情况下值得再建一个旁路"。

实测：

    玩家：我离开天道宗，一路往青木山脉方向走，赶了三天的路
    → ⏰ 太初历…仲夏·午时初刻（3日后）（+4320分）

4320 = 3 × 24 × 60，**正好三天**。旧机制下这条得先由 S1 猜倍数、再由 R2 按段数折算，
两步都可能偏。

### 已知缺陷

**~~`/move` 命令从来没生效过~~** —— **2026-10-08 退役**：整个移动标记机制（`{移动}` /
`/move` / 终端菜单 / `/api/move` / 引擎移动兜底）都删了。理由见下面「位置」那一节：
位置改由 L3 出 `去向` + 代码落坐标，而"让前端给引擎一个树上合法路径"正是它们存在的**唯一**理由。

`gc.handle_command()` 里没有 `/move` 分支，它会掉进最后的 `else` 打到「未知命令」并返回
`'continue'`；而调用方是**先调 `handle_command`，返回 `'continue'` 就直接跳过**：

```python
cmd = gc.handle_command(raw)
if cmd == 'continue': return 'continue'      # ← /move 死在这里
return resolve_move_markers(raw, ...)        # ← 只有 {移动} 能到这
```

`{移动}`（不以 `/` 开头）不受影响。修法是给 `handle_command` 加一条 `/move` 放行分支。

**移动没有"到不到得了"的校验**：点地点树会无条件把玩家移过去（L3 只事后补旁白），
远距离瞬移不会被拒。**瞬移本身没有拒绝机制**——要么在 L3 里加一道可达性判断，
要么前端按距离限制可选范围。这是设计缺口不是 bug。

> 顺带一提：瞬移**会**被如实计时（`本轮耗时分钟` 由 L3 判断），不会出现"闪过去却零耗时"。

**★ L3 会写出地点树外的位置，而当轮的所有节点能力会一起静默失效**（2026-10-08 实测）。

L3 被要求"位置必须复用已知分段"，但它会往真路径后面**接话**。实测那一句：

    玩家：我离开天道宗，一路往青木山脉方向走去，赶了三天的路
    → L3 写的位置：苍云大陆·东域·青木山脉方向（离天道宗三日脚程）

`get_location_context()` 逐段最长匹配，任一段对不上就整体返回空——实测这条路径
**链长 0、产出 0 条**（对照 `苍云大陆·东域·青木山脉` 是链长 3、产出 4 条）。后果是同一条
链上挂着的四个消费方**在当轮全部拿不到东西**，而且**一个字都不报错**：

| 谁 | 失效方式 |
|----|---------|
| L1 | `当前节点` 为空 → 判断"谁听得到"时看不到灵气/势力/规矩 |
| L3 | `当前节点` 为空 → 旁白质感失去依据 |
| R4 机缘导演 | 找不到产出表 → 返回空，**连日志都没有**（它只在"有表"时才说话） |
| 网页地点树 | 当前位置不在树里（前端已按这条做了提示） |

**这条已经在真实运行里造成过一次错误叙述**：下一轮玩家在青木山脉打坐八个月，
L3 的旁白写「青木山脉**灵气偏薄**」——而地点属性写的是 **`灵气：浓郁`**。
那一轮它拿到的节点链是空的（位置是上面那条接话路径），所以"浓郁"根本没进模型，
它改用世界规则「灵气持续衰减」现场编了一个理由。

修法两条，方向相反，**未定**：

1. **收紧出口**（与 README 既有方向一致）：在 L3 的 prompt 里把"位置必须是树上的完整路径、
   不许接话"写成硬约束，并在代码里校验新位置能否解析，不能就退回出发地。
2. **放宽入口**：`get_location_context()` 解析失败时回退到**最长可解析前缀**
   （"青木山脉方向（…）" → 祖先 `青木山脉`），让节点能力至少拿到最近的真实锚点。
   代价是漂移会被掩盖——而"位置不能漂"是 `location_test.py` 专门盯的保证。

**`group` 这一档从未被触发过**（历史运行 + 探针全算上）。五档里实际活着的是
`public`/`area`/`private`；`hidden` 偶发；`group` 是死的——prompt 里第 3 条的
「宗门/帮派/组织内部」这个条件，模型基本不用。

**公开事件传不远**：实测"站在落霞坪中央高声宣布"，`感知分发` 里**始终只有白鹤一人**——
两段外的陈守贵和柳明溪一次都没收到。**世界听起来比实际空**。

> 这条的**成因已经变了**。原来是因为「R3 只做过滤不做添加」，L1 少写就真少了；
> 删掉 R3 的距离过滤之后，成因变成**纯粹的 L1 判断问题**——L1 就是只给最近的人写感知。
> 修法也跟着变：要么在提示词里让 L1 对公开事件多写几个人，要么给 L1 开推理
> （实测开推理后感知人数稳定在 1，但那只测了悄悄话；公开事件待测）。
> `节点传播` 那条路不受影响——实测长啸一次就传到了 2 段外的两个人。

| 阶段 | 做什么 | 状态 |

| **0** | 核心功能跑通，**推理全开**，不测性能 | ✅ 已跑通（见下） |

#### 阶段 1 的一条命令

**墙钟（每组 3 遍取中位数，极差已收到 1.1~1.6×）**

| 组 | 中位 | vs 基线 |
|----|-----:|--------:|
| 基线（推理全开） | 192s | 基准 |
| **只关 L1** | **120s** | **1.7×** |
| 只关 L2 | 169s | 1.2× |
| 只关 L3 | 167s | 1.3× |
| 全关 | **40s** | **4.6×** |

> ⚠️ n=1 时同一配置两遍差 **77%**（181s vs 321s，被一次 101.7s 长尾拉起）。
> **3 遍之后才可用。** 单跑一遍的结论就是噪声。

**但质量指标把结论反转了。** 粗指标（套路词、越界、交易一致性）五组全干净，
看不出差别。于是加了一条针对性的：L1 产出的感知里有多少表达了"看不透"——
这需要一个**与玩家修为相近**的观察者才有判别力，所以专门写了
`scenarios/近修为剧本.txt`（把人带到炼气初期的韩铁柱面前）。

| 组 | 感知份数 | 含"看不透"式表达 | 占比 |
|----|--------:|----------------:|-----:|
| 基线（L1 推理开） | 12 | 11 | **92%** |
| 只关 L1 | 12 | 7 | **58%** |

**关掉 L1 的推理，"看不透"率从 92% 掉到 58%。**

所以 **L1 的推理是承重的**：它省得最多（1.7×），代价却是废掉设计枢纽。
"全关 4.6×"这个数字很诱人，但它不是一条可走的路。

阶段 0 要确认的三件事，**都已确认**：

| # | 要确认的 | 实测结果 |
|---|---------|---------|
| 1 | 失真感知能产出"看不透"，不是千篇一律 | ✅ 玩家朝后山喊话，化神后期的宗主收到的感知是"声息单弱…修为不过炼气"，他的回应是**「三重禁制之下，你一个炼气弟子的声音能递到我耳边——先说说，你是怎么做到的」**——不对称本身生成了剧情 |
| 2 | L3 能守住交易一致性 | ✅ 玩家谎称掏出"一百块上品灵石"买本命法宝 → **双方持有物都没变**，旁白写"指间空落…石阶上并无锦袋落下"，并给两个 NPC 注入了破裂观察 |
| 3 | L2 只出意图、L3 落实，链路能闭合 | ✅ L2 出「给予：取一瓶辟谷丹递给他」，L3 核对白鹤确实持有、转移成立；失败的那几笔一笔没成 |

另外一个意外收获：NPC 会**跨轮次记住事情**——玩家第一次捧出八块碎灵石、第二次改口说三块，
白鹤的回应是"三块？你方才捧出来的明明是八块"。

> 地理与配置在阶段 0 一起搬到了 `.map`。改配置不用重启：编辑器保存后会热重载。

### 世界配置（`世界.map` → `配置` 行）

| 键 | 作用 | 默认 |
|----|------|------|
| `生命值体系` | `"数值"` / `"文本"`——决定像游戏还是像小说 | `数值` |
| `玩家初始数据` | 用哪个玩家档 | 世界决定 |
| `NPC_附近距离_段` | 附近 NPC 候选范围（地点树段数，R3 用） | 3 |
| `NPC_上限_MAX_*` | 各 NPC 表截断上限，键名 = `NPC_上限_` + `CAP_MAP` 的值 | 见 `B3NPCLayer.CAP_MAP` |
| `心跳间隔_小时` | 后台 B1a/B1b/B2 触发间隔 | 12 |
| `机缘_间隔_小时` | 同一地点两次机缘机会之间至少隔多少游戏时间。**默认按实测定**，见「机缘导演」节 | 0.5 |
| `机缘_每日上限` | 每个游戏日最多得手几**件**。**设 0 = 关掉机缘** | 2 |

新增配置项只需加键值对，代码里用 `get_config(key, default)` 读，有兜底不会破坏现有世界。

### 程序配置（`common/base_cnf.py`）

```python
LAYER_MODEL_OVERRIDE = {
    'S1': {'thinking': False, 'timeout': 20, 'max_retries': 1},   # 关推理
    # 'L1': {'thinking': False},   # 阶段 1 实验：一次只取消注释一层
    'B1a': {'temperature': 0.3},
    'B1b': {'temperature': 0.9},
}
```

- **推理开关**：`thinking=False` → 请求体塞 `payload['thinking'] = {'type':'disabled'}`。
  推理 token 实测占输出的 67~96%，**按输出计费**，关掉同时省延迟和成本。
- **S1 的降级契约**：短超时 + 不重试（与大模型层**相反**）——它失败就走规则兜底，
  等它不如不等。**旁路绝不能成为新的故障点。**
