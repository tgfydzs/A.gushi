## 一、这条路要走到哪

**终点**：世界是一张**可手写、可视化、可生成**的图；游戏里它是一张常驻小地图；
编辑器是同一个组件的另一种模式；"在节点之间"终于有地方表达。

**不是终点**：不做实时协作、不做多用户、不做在线托管。世界数据的作者只有你一个，
编辑器只监听 127.0.0.1（沿用现有约定，无认证）。

### 1A.1 拆解（沿路推进，已完成 2026-10-08）

> 这一步兑现的是 prompt 里**早就说给模型听的一句承诺**（`L3_settlement_sys.txt`：
> 「走得到就到，走不到就到路上，代码会按你判的耗时把他放在路上」）——
> 而在此之前**代码从没做过这个动作**：L3 给一个走不到的 `去向`，代码照样瞬移过去。
> 那不是"功能没做"，是**对模型的一句假话**。

| 步 | 产出 |
|----|------|
| S3-a | L3 多吐一个 `行程`（`刚上路/半路/将到/到了`，**语义不是数字**）；两份 prompt 都补了条款 |
| S3-b | `B1WorldLayer`：`road_between` / `route`（按跳数最短路）/ `road_point`（**二次贝塞尔**）/ `on_road_at` / `segment_at` / `road_desc`——**`路列表` 第一次进引擎判定** |
| S3-c | `gc.set_position_on_road(road, t, frm)` + `gc.advance_travel(state, dest, frac)`——按**整段路程的几分之几**落点 |
| S3-d | `location_desc` / `location_context_for`：**「在路上」终于说得出口**（原来 `path_at` 静默塌缩成最近地块） |
| S3-e | L1 与 L3 的「当前节点」改由引擎算好传入；`移动信息`/`本轮含移动` 两条**空管道删掉** |

**四个当场抓到的真问题**（都不是靠读代码看出来的，是跑出来的）：

1. **`road_point` 假设路径线从 `从` 排起**，而人可能从任一端走 → "从落霞坪往天道宗走 15%"
   被算成"从天道宗往回走 15%"，**方向整个反了**，坐标看着还挺正常。修：`set_position_on_road`
   收 `frm`，反向时取 `1-t`。
2. **「在路上」永远为假**：自动布局的 `范围` 半径是**画图**用的（天道宗 r=104、东域 r=252），
   整条路的走廊都在某个区域的圈里。实测 41 个地块坐标 0 个在路上。修：`on_road_at` 另立判据
   （叶地块 / `PLACE_CORE` / `ROAD_CORRIDOR`），`locate()` 不动。
3. **描述措辞方向反了**：路的 `从/到` 是书写顺序，写成"A到B的路上"会让 L3 以为他在从 A 去 B。
   修：改成方向中性的"A—B 之间的路上"。
4. **路由的采样表与邻接表也得进 `reload_world` 的缓存清理**，否则改了地图还记着旧路。

**风险（计划里就点了名的那条）**：那张词表是我猜的。**真机第一轮就命中**——
L3 吐的是 `"刚上路"`，日志：`🚶 行进：落霞坪 → 南域 走到 15%（第 1/4 跳：落霞坪 → 天道宗，t=0.6，刚上路）`，
地图上显示「天道宗—落霞坪 之间的路上（半路）」，位置真的落在曲线上。**词表暂不改**，
多跑几轮再照模型实际吐的词收口。

**已知的粗糙处**：`road_desc` 报的"半路"是**这一跳**的进度，而 `行程` 是**整段**的进度，
两者粒度不同（下一轮 L3 看到的是"这一跳"）。要不要统一留到有 `段` 数据之后再看——
`段` 才是"走到哪了"该有的粒度，而 `.map` 里现在 0 条段（属于阶段 4 的世界生成器）。

**真机验证（2026-10-08，三轮）**：

| 轮 | 玩家说 | L3 的 `去向` | 结果 |
|----|--------|-------------|------|
| 1 | "我离开天道宗，一路往东，去青木山脉看看" | `苍云大陆·东域·青木山脉` | 坐标落到青木山脉 ✓ |
| 2 | "…然后动身去东域坊市灵虚集" | `苍云大陆·东域·东域坊市·灵虚集` | 坐标落到灵虚集 ✓ |
| 3 | "我就在原地站着不动" | `''` | **位置纹丝不动** ✓（正是要的行为） |

两条实情：L3 给的是**完整路径**而不是短名——`set_position` 走"名字↔路径双射"，两种都吃得下
（**这个双射当场救了场**）；三轮里 **L3 一次都没偷偷写 `位置`**，玩家增量里只有
`体力状态`/`当前心情` ✓。

**0d 是全计划最关键的一步**：它证明"换了形状，世界一点没变"。做不到这一点，
后面所有东西都建在流沙上——所以它是硬门，不许跳过。

### 2 拆解（字段编辑器，已完成 2026-10-08）

**形状**：`GET /api/map/edit` 给一份**扁平表单**，`POST /api/map/save` 收回去。编辑器是
全屏浮层（不是面板）——322px 的栏里改 41 个地块的属性不现实。左边那张图**就是小地图那个
组件**（同一个 `buildMapStatic`），只是放大、点＝选中。

| 步 | 产出 |
|----|------|
| 2a | `map_io`：`flatten_world` / `nest_world` / `validate_edit` / `canonicalize` / `save_map` |
| 2b | `map_io`：`to_edit_form` / `from_edit_form`——**线上形态里每个值都是 `.map` 里的写法** |
| 2c | `GET /api/map/edit`、`POST /api/map/save`（忙则拒；成功则热重载） |
| 2d | `gc.reload_world()`：把 `.map` 重新盖到**活着的**世界字典上 |
| 2e | 前端：实体列表 + 筛选 + 检视器（名/属于/说明/任意键值/几何文本），`S.edit` 一套状态 |

**三条设计决定**（都是为了"只有一处真相"）：

1. **字段值就用 `.map` 的语法**（`[a,b]`=列表、`是/否`=布尔、纯数字=数字）。
   类型规则在 `_parse_value`/`_fmt_value` 里已经存在且被往返测试钉死，再用 JS 判一遍
   就是抄一份规则——抄的那份迟早和 Python 漂开。顺带：字段框里显示的就是"这条写进
   `.map` 会是什么样"。
2. **值里不塞原生 JSON**。送原生 JSON 的话 JS 得自己判类型，就回到上面那条。
3. **前端不拼 `.map` 文本**。写盘三查（校验 → 往返自检 → 备份）**全在服务端**。

**写盘三查**（`map_io.save_map`），任一不过就**一个字节都不写**：

| 查 | 挡的是什么 |
|----|-----------|
| `validate_edit` | 属于悬空 / 重名 / 路端悬空 / 空值 / 键含分隔符 / 几何指向不存在的地块 |
| **往返自检** | `emit → parse → flatten` 必须回到一模一样的模型。挡"改一条、顺手丢另一条" |
| 备份 | 写到 `_备份/世界.map.<时间戳>`（**进 .gitignore**：历史上每一版交给 git 才有 review 价值） |

**这道往返自检当场抓到了三个真 bug**（这就是它存在的意义）：

1. `范围` 解析回来是 **tuple**，过一趟 JSON 变 **list** → "往返不一致"。修：编辑模型一律 list。
2. `产出` 用通用值语法吐成了 `[{'物品':…}]` 那种没人看得懂的东西 → 修：走它自己的 `物品:概率(条件)` 语法。
3. `flatten_world` 与 `from_edit_form` 两个构造函数的**键序不一致** → 误报"键序变了"。

**还有一个只在浏览器里才暴露的**：Flask 的 `jsonify` **默认按键排序**，于是编辑器原样存回
就会把整个文件重排——改一个字段 → **159 行 diff**。两道防：`app.json.sort_keys = False`，
外加 `canonicalize` 落盘前按盘上顺序对齐实体序与属性键序。

**验收（用户给的标准）**：改一条属性 → **只动 1 行**。实测：改 `灵气` → 1 行；**再新增一个
自由字段**（`禁忌=`）→ 仍只动 1 行，新键追加在行尾、别处一字未动。`map_edit_test.py` 32 项
把这几条钉死了（含"不改任何东西连存三次，逐字节相同"的幂等断言）。

**字段不定**：检视器不限定键名，加什么键都行，LLM 侧照旧从 `_属性` 读——用户要的
"字段不定，交由 llm 判断"就是这么落的。

### 2.6 标签为什么"放大也分不开"（用户报的，2026-10-08）

用户看出来的原话：「字体缩放不是线性的，放大后还是重叠」。根因是**字号是画布单位**：

`.mplace text { font-size: 34px }` 里的 34 是 **SVG 用户单位**，缩放时文字与几何**一起**放大，
于是标签间距和字宽**同比**变化——**重叠跟缩放无关，放大再多次也分不开**。
同一个 34 在 375px 的面板里只有 8.8px（太小）、在 1262px 的编辑器里 29.5px（太大），两头都不对。

改成地图标签的常规做法：

| 改 | 怎么做 |
|----|--------|
| **字号恒定屏幕像素** | JS 按当前缩放反算，挂成 CSS 变量 `--mlabel`（11.5px）。光晕 `--mhalo` 同理。**点击热区 `--mhit` 是例外**：它跟着那个点自己的屏幕大小走（`mapReachPx`），恒定会在缩小时抢邻居——见 §3.6 末尾 |
| **标签逐个避让** | `applyMapLabels`：只在不跟已放下的框相交、且落在视野里时才 `.mplace.sel`… 显示。41 个 → 820 对，很便宜 |
| **优先级随缩放翻转** | 缩着时区域名赢（看格局），放大时叶子名赢（看细节）。不翻转的话，缩进天道宗那一片会被"天道宗"三个字把 7 个子地块全挤掉 |
| **换算只能有一个 scale** | 见下 |

**两个只有跑起来才发现的**：

1. **"全显/只显区域名"两档太粗**：实测要缩到第 14 档才跳档，中间十几档全是"区域名 + 一片空白"。
   逐个摆放之后，放大 = 名字一个个冒出来。
2. **x/y 各算各的 scale**：`preserveAspectRatio="meet"` 是**等比缩放 + 居中留白**，
   分开算会在浮层（宽高比与 viewBox 不同）里得到一个**被拉扁的坐标系**，标签照着错的间距避让
   ——实测 1145px 宽的全屏地图反而只放下 10 个名字。修：统一走 `mapScale()`；
   顺带把全屏地图从"写死高度"改成"宽度驱动"（方形地图写死高度等于把宽度全浪费掉）。

**实测**：面板默认 15 标签 / **0 重叠**；瞄准天道宗放大 9 档，7 个子地块出来 5 个 / 0 重叠；
全屏（1465px）**38/41 标签 / 0 重叠**。

### 3 拆解（几何编辑，已完成 2026-10-08）

**停点 D「编辑器完整」**。四件事：拖节点 / 拉曲线 / 连线成路 / 新建实体。

| 步 | 产出 |
|----|------|
| 3a | 编辑器左图上拖 `.mdot`＝改 `坐标`；选中一条路出 `.ectrl` 控制点，拖它＝改 `路径线` |
| 3b | 拖动**只改数字**（`S.edit.view`），松手记进 `S.edit.geo`；保存时服务端 `apply_geo_patch` **生成文本** |
| 3c | 「＋ 新建地块 / 新建路」：自动补 `坐标`（视野中心）+ `范围 圆(16)` / 一条直线 `路径线` |
| 3d | `order_places_dfs`：地块列表按 **DFS 前序**排——不加这一步，新建的**子**地块会与 emit 顺序错位 |

**三条设计决定**：

1. **前端不格式化浮点。** `.map` 里坐标的写法是 Python 的 `repr(float)`——`170.0` 写成
   `170` 就变成 int 了。在 JS 里再抄一份格式化规则就是两处真相。所以前端只报
   「我把它拖到了这儿」（数值），**文本由服务端生成**。代价：拖动后检视器里的
   「坐标」文本框**过期了**，所以它会被标成"拖过"（而不是悄悄显示一个旧值）。
2. **拖地块要带着路端点走。** `路径线` 的两端本来就**是**那两个地块的坐标
   （`auto_layout` 这么生成，`road_point` 也靠这个前提），不跟线就从空地开始。
   于是"拖动只动一行"对**有路的地块**不成立，而且**不该**成立——准确的不变量是
   **「动 `坐标` 那行 ＋ 连着它的那几条 `路径线`」**，测试就按这个数断言（1 + 度数）。
   这是派生改动，所以**列在回执里**。
3. **新建必须顺手补几何**：没 `坐标` → 地图上根本不出现；没 `范围` → `locate()`
   认不到它，站上去只会是"在路上"；没 `路径线` → 画不出来（校验器也会拦）。

**跑起来才抓到的三个**：

0. **拖地块根本不行，而且测试看不出来**（用户报的"地块位置还是不能动"）：可拖的目标只认了
   那个可见的小圆点 `.mdot`（6~9 画布单位），可手按下去时**最上面那个元素是 `.mhit`**
   ——一个专门给点击用的大透明圈，它**盖住了** `.mdot`。于是 `closest()` 一律返回 null，
   **地块一次都拖不动**（实测：圆心正中也不行）。
   之所以测试是绿的：我直接 `dot.dispatchEvent(pointerdown)`，那会**跳过命中测试**，
   而真人的手**必须**经过它。修：认**整个 `.mplace` 组**；验证也改成走
   `document.elementFromPoint()`。
   > 教训：**别在"你以为的那个元素"上派发事件**——派发到哪就是哪，浏览器不会替你命中测试。


- **`setPointerCapture` 会把整个拖动静默掐掉**：它对合成事件（pointerId 不对应真实指针）
  抛 `NotFoundError`，而它**在移动逻辑之前**；监听器里的异常又不会冒到
  `dispatchEvent` 的调用方，外面**完全看不出来**。捕获本来就只是优化（监听在 `document` 上），
  但不能让它把后面那段带下去 → try/catch。
- **新建子地块被往返自检拦下**：新条目追加到列表末尾，可它其实是中间某个节点的孩子，
  `emit → parse → flatten` 回来的顺序对不上（报"地块[17].名 '西域' → '新地块1'"）。
  修：收尾时把地块列表排成 DFS 前序。

**实测（浏览器里真拖）**：拖地块 → 文件里 `坐标 青木山脉 (416.4,-105.2)` →
`(548.0796,-180.4455)`，连着它的两条 `路径线` 端点跟着走，回执里列了出来；
新建与连线也都落成对应行。**节点跟手**：光标 (1091.9,249)，节点落点 (1092,249.1)。

### 3.2 交付后用户报的第四个：**地图不实时**（2026-10-08）

用户原话："删除路，曲线不能点了，但是线还在，不实时问题"。

**真因**：编辑器左侧那张图是 `S.edit.view` —— **开编辑器时拍的一张快照**
（`GET /api/map/edit` 只给那一次），而表单是活的。删掉一条路，快照不知道，
于是那条路**照旧画着**；点它又选不中（按名字去表单里找，找不到）——
一条**看得见、点不动、也删不掉**的幽灵线。

同一根因还压着另外三种操作：删**地块**（连着它的路该一起没）、
删**几何行**、**改名**（改的不只是标签：`属于`、路的 `从/到`、`A-B` 拼出来的路名、
几何的键，一整串引用都得跟着走）。

**修法**：加 `POST /api/map/preview` —— **只看不写**，把手上这份表单交给服务端，
用**保存那条流水线**（新抽出来的 `map_io.prepare_edit`）算一遍，再把图还回来。

| 为什么这么修 | |
|---|---|
| 不在 JS 里照着删 | 级联规则在 `map_io.cascade` 里（删地块连带删路、改名连带改引用）。抄一份到 JS，抄的那份迟早和 Python 漂开——S2 那次"改一个字段重排 159 行"就是这么来的 |
| 图与线上同一段代码 | `engine.map_view()` 的算法抽成模块级 `map_view_of(w, st, location)`，线上和预览**调同一个函数**。测试里钉了"原样预览 == `/api/map/edit` 的视图" |
| 预览不写盘 | 它不校验（半成品也得能看）、不备份、不落盘、不碰运行中的世界。测试里加了"预览一个字节都没写" |

**改名还要多一步**：预览只画图，不会把改过的引用塞回表单。不同步的话
"图上叫 `东域·改名试-西域`、表单里还叫 `东域-西域`"——点得中、选不中。
所以预览**顺带把改名映射报回来**（`{地块:{旧:新}, 路:{旧:新}}`），前端照着改；
规则仍然只有 `detect_renames` 那一份，前端只是把映射应用一遍。

**两个补丁，都是"宁旧勿缺"**：

- **几何写坏就拒答**：`from_edit_form` 会把解析不出的那一条丢掉，照丢掉的画出来就是
  "某块地凭空不见了"。所以 `坐标/范围/路径线` 的条数对不上时预览直接拒答
  （前端留着上一张图）。字段行没写完不拦——那些不影响画图。
- **手改几何也要跟上**（不然"改完坐标图不动"还是同一个毛病）：几何框 `input` 后
  **停手 500ms** 再算一次，且这一路**不出声**（边打边算，中间态认不出是常事）。
  **名字框不参与**这条：半个名字会连带改一串引用，只能等失焦。

**顺带挖出来的一个真缺陷**（`detect_renames` 补了一次配对）：**新建之后又改名**
——新实体在盘上没有对应位置，位置比对**轮不到它**，它的 `坐标` 键就还挂着占位名，
落盘时被当成"悬空几何"**静默清掉**（新建的地块就此丢了坐标，图上不出现、
`locate()` 也认不出）。编辑器自己提示的正是"名字是占位的——先改掉再保存"，
所以这条路走的人不会少。补的判据：一个**没人认领的新几何键** ＋ 一个**没有几何的新名字**
正好各一个 → 就是一次改名（限 1↔1：多对多没有可靠的顺序信号，宁可让用户看到"连带删掉"的提示）。

> 教训与 3.1 是同一条的反面：3.1 是"别在你以为的元素上派发事件"，
> 这一条是"**别相信你手边的那份数据**"。视图是快照，表单是活的——
> 凡是"表单改了、视图没改"的地方，都该问一句**谁才是真的**，然后让它去算。

1. **热区半径收窄**——上面那条 `max(16px, …)` 的**下限是错的**。未缩放时天道宗院里

   手势当场丢。修：`[data-mapbox] { user-select: none }`（CSS）、

   那几个按钮除外**——它们的默认行为要留着）、`document` 上一条 `dragstart` 兜底
   （HTML5 的"拖着选中的字去搜索"在有些路径上绕过 `pointerdown`）。
   实测：手工造一段选中 → 按下 → `rangeCount` 归 0 且 `defaultPrevented` 为真；
   ＋/－ 按钮的 `defaultPrevented` 仍为假。

## 四、参考实践（凭记忆，本机检索不通，**未核链接**）

| 来源 | 可借鉴的 | 对我们意味着 |
|------|---------|-------------|
| **MUD / MOO / LPMud** | 房间扁平、出口是**一等对象**（可单向、可绕回、可带条件）；四十年验证过的形状 | 我们的 `地块 + 路` 就是它。⚠️ **但它的"一切皆房间"不能照搬**：MUD 里你永远站在某个房间里，所以长路只能拆成一串"走廊房间"；我们没这个限制——**只穿过的地形用 `段` 表达，不必假装它是个地点** |
| **Tiled / LDtk**（瓦片地图编辑器） | 自定义属性是**任意键值表**；工程文件是纯文本；进游戏前有一道 **cook/导出** | 我们的"自由键"正是这个；我们用**加载时解析**代替 cook（项目禁止构建步骤）。LDtk 还把**字段定义**与**实例取值**分开 → 编辑器有表单可渲染，而数据仍然任意 |
| **Godot `.tscn` / Unity YAML** | 文本是真源，编辑器**按固定顺序重写**，靠 **uid** 而不是路径做稳定引用 | 我们的"保序 emit"就是这条；uid 是对"改名=存档失效"的正解之一 |
| **Paradox（EU4 等）** | **形状存图，语义存文本**（省界位图 + 定义文件） | 若将来要给区域画**填充形状**，这是正路；我们只画线（`路径线` 折线点）所以暂不需要 |
| **Ink / Twine / ChoiceScript** | 手写叙事 DSL 能长期维护；Twine 证明 **GUI 作者与文本作者可以共存** | 我们的 `.map` 不是孤例，DSL 路线可行 |
| **Dwarf Fortress / RimWorld** | 世界**生成后冻结**；生成时可预览与重掷 | 阶段 4 的正解：**LLM 出草稿 → 校验器 → 人裁 → 入库冻结**，绝不让生成结果直接进存档世界 |

**两个族而不是一个族——这是从 MUD 反推出来的界**（用户纠正了我先前给错的说法）：

> MUD 把所有东西塞进"房间"这一族，代价是必经之地全变成了**假地点**（走廊房间）。
> 我们分开：**能停下来的 = 地块；只能穿过的 = 段。**
> 于是"在路上"= `行进 = {路, 段, 已行, 预计}`，而**位置格永远是一个真地块**——
> 这正好修掉我们实测到的那次事故（L3 把散文塞进位置格）。
> 曲线是**画**出来的；"途经一座 8000 米雪山"是**数据**，但它属于**路的段**，不属于地块。

## 六、风险与对策

| 风险 | 对策 |
|------|------|
| 迁移丢能力（静默） | 语义基线对照（已建）+ 自检六条；**对照不过不许删旧代码** |
| 新格式引入新的静默失效（拼错保留键） | 近似键检测 + 死键报告（项目已栽过一次同款） |
| 编辑器手滑毁世界 | 保存前自动备份 + dry-run 校验 + **写盘后不热替换运行中的世界** |
| 地图组件把游戏页拖死 | 文字信息与地图解耦（地图挂了照常显示位置/在场）；静态层只渲染一次 |
| round-trip 不保真（GUI 保存吃掉手写排版/注释） | 保序 emit；**凡是要活过保存的东西必须是字段**（`说明=`） |
| 范围失控 | 严格 2（属性）先于 3（几何）；每阶段独立可停 |
| 老存档失效 | 位置字符串继续当键；改名走迁移；阶段 0 不动存档格式 |
