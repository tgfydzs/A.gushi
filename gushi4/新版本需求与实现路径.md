# 第 0 部分 · 三条设计原则

后面每一条需求、每一步施工，都是从这三条推出来的。**先立它们，是为了在取舍时不用每次重新论证。**

## 0.1 成本结构：层数是线性小项，判断数是乘法项

用项目自己的消融数据（`gushi4/设计方案.md:715-720`，主剧本 3 遍，关键路径 = `L1 + max(L2) + L3` 已被验证）：

| 组 | 关键路径 | 反推该层**推理**的边际贡献 |
|---|---:|---:|
| 基线（推理全开） | **41.6s** | — |
| 只关 L1 | 24.6s | L1 = **17.0s** |
| 只关 L2 | 34.6s | L2 = **7.0s** |
| 只关 L3 | 33.1s | L3 = **8.5s** |
| 全关 | 9.0s | 合计 32.5s |

（三类相加 32.5s ≈ 41.6 − 9.0 = 32.6s，内部自洽。）

再看输入侧（实测 `gushi4/log/gushi4.log` 一轮）：

| 层 | 输入（其中**缓存命中**） | 输出 | 其中推理 | 墙钟 |
|---|---|---:|---:|---:|
| L1 | 5719（**5248**） | 3116 | 2915（94%） | 18.1s |
| L2 | 3090（2816） | 325 | — | 4.1s |
| L3 | 5823（4480） | 252 | — | 3.4s |

**结论**：三层的输入量级相当，且 78–92% 是缓存命中的系统提示词——**几乎不花钱、也不花延迟**。
真正付钱和等时间的是**输出那一列，且输出里 90% 是推理**。

> 所以"多一层"的真实代价 ≈ **该层自己的推理量**，不在"多了一层"本身。
> 而推理量取决于**这一层要判几件事**：L1 判 6 件 → 3116 输出、18s；L3 判 1 件 → 252 输出、3.4s。

**推论（贯穿全文）**：

- **一层一职**。不是美学，是成本：判断数 → 推理量 → 延迟与账单。
- 合并两层的收益是"省一个往返（秒级）"，代价是"单层判断数翻倍 → 推理量超线性上升"。**别合并判断，要合并的是往返之外的机械部分。**
- 关键路径上的层用**并行**摊，不用合并摊。

## 0.2 判断归 LLM，落盘与兜底归代码

gushi3 的原则 P1/P2 照搬，但加一条**本次审计得出的新纪律**：

> **删掉一条确定性规则时，必须同时指名它的替代者，并让替代者接管那份职责。**
> 没有替代者，就不许删。

这条的价值有直接证据：`gushi4/移植缺口.md` §1 的十条，全部是"规则删了、替代者没接上"的形状
（时间层的尺子与天花板、传播的判决与兜底、事件上下文的清空、叙事去重缓存、客制化钩子…）。

## 0.3 几何只给眼睛

gushi4 的硬底线，保留：**节点坐标与路段路径线绝不进 LLM 输入**。
不得用几何距离算听不听得见 / 消息传多远 / **走多久** / 谁先动手。

⚠️ 这条与"耗时"有张力，**处理方式见 R-d·4**：耗时由 LLM/玩家声明给，几何只负责"把人落在路的哪个点上"。
方向是 **耗时 → 几何**，不是 gushi3 的 **几何 → 耗时**。

# 第 1 部分 · 功能需求（行为契约）

每条四要素：**行为 / 判据 / 失败退路 / 验收**。
验收一律要求"能用代码或离线测试判定"，不接受"看起来对"。

## 1.A 一轮的时序契约

| # | 需求 | 判据与失败退路 | 验收 |
|---|---|---|---|
| **R-a·1** | 一轮 = 一次玩家自由文本 → 一次完整推进 → 一次时钟推进。没输入就不推进（后台心跳除外） | 空输入必须被跳过，不得产出一轮 | 空输入 → 状态零变化 |
| **R-a·2** | 关键路径顺序固定：**事件 → 感知 → 角色（并行 per NPC）→ 结算 → 时钟** | 角色层必须并发（每 NPC 一次）；事件/感知/结算各 1 次/轮 | 断言调用数与并发度 |
| **R-a·3** | 每轮**只有一个**客观状态写入口（结算层）。事件层只改名单与可见性，感知层只产文本 | 越权写入必须被代码丢弃并告警 | 白名单函数 + 越权写入被丢的测试 |
| **R-a·4** | 一轮开始先取**全量**快照（供撤回）。快照必须覆盖所有会变的状态，**含后台调度计时** | 漏项 = 撤回不干净 | 快照往返测试 + 「撤回后计时也回滚」的测试 |
| **R-a·5** | 一轮产出一组标准事件（场景/对白/旁白/时间/轮次…）。终端与网页是**同一接口的两个实现** | 引擎自己不得调用 `input()` | 两个渲染器共用一个接口的测试 |

## 1.B 信息边界（最硬的一组，全部靠代码强制）

| # | 需求 | 判据 |
|---|---|---|
| **R-b·1** | **一个 LLM 调用只能属于一个信息域**（世界域 / 角色域 / 结算域），跨域合并非法 | 每次调用点标注它属于哪个域，代码可查 |
| **R-b·2** | 世界域可见：事件、全员名册（名 + **真实**实力 + 位置）、玩家真值、幕后情报；产出**只能**是失真后的感知 | 输入构造集中在世界域一处 |
| **R-b·3** | 角色域每 NPC 一次，只见**它自己那份**失真感知 + 它自己的 11 张表。**不得**见玩家实况 | 输入里没有玩家实况字段 |
| **R-b·4** | 结算域见玩家全量实况 + 各 NPC 客观侧（**2 张表**）+ 所有意图；**唯一**客观写入口 | `sanitize_objective_delta` 只放行 2 张 |
| **R-b·5** | 边界由**代码**强制，不靠 prompt 自觉。**列出每张表的唯一写者**（见下 §1.B.1） | 每张表恰有一个写者，测试断言 |
| **R-b·6** | **凡声称"代码会执行"的边界，必须真的在代码里执行**；否则不得在文档或 prompt 里声称 | 见 `I-03`（这条是审计 §1.3 的直接教训） |
| **R-b·7** | 位置（坐标）只有代码能写；LLM 只能给**地名 / 行程** | 位置字段不在任何 LLM 写白名单里 |
| **R-b·8** | 一个 NPC/玩家**不被看见**时，结构上就拿不到——不是靠"提示它别说" | 上下文里**不含本轮玩家原话**（该知道的走感知进入） |
| **R-b·9** | **NPC 的言语不构成客观拦阻**：判"玩家能不能动"只许看**客观动作**（有人物理拦住 / 门禁 / 受伤 / 路不通），不许看"某个 NPC 说了不行" | 否则一句台词就能把玩家钉死，而且此后进入上下文、自我强化（实测：白鹤只是问话、未动手，结算层却判"站定未动"） |
| **R-b·10** | **世界级事实的权威只有两个来源**：数据（世界规则 / 世界状态 / 知识列表）与结算层的**显式**判定。NPC 对话里的断言只是**那个 NPC 的信念** | 否则任何 NPC 都能发明世界规则，且一次就永久成立（实测：白鹤编出"出山令牌"，数据里没有这条） |
| **R-b·11** | **参与者 ≠ 接收者**。`involved` 只表示"这个事件里有谁"，`scope` 表示"**本轮这条信息**给谁"。私密信息只给直接对象 | ⚠️ 反例（gushi4 实测）：一条"传识"私密传念被广播给名单里 4 个人，且各人以"玩家**对我说**"的口吻回应。gushi3 有「候选NPC ≠ 收到信息」这条原则，gushi4 删了 |
| **R-b·12** | 边界执行的**方向只能是减法**：可以做"删掉不该收的人"（防幻觉 / 执行 hidden / 执行 private），**不得做"给谁补一条"** | gushi4 的 `R3.enforce` 有唯一的加法点（给名单里没写感知的人补一条），正是 §1.12 那个泄漏的执行者。加法会让"没人给写感知"这个**合法状态**（R-c·4）被消灭 |

### 1.B.1 表归属表（写进代码，别写进文档）

| 表 | 唯一写者 | 域 |
|---|---|---|
| 知识记忆Memory · 信念Belief · 性格Personality · 生活目标Goals · 好感度Relationship · 观察Observation · 对玩家观察PlayerObservation · 待解释事件PendingReasoning | 角色层 | 角色域 |
| 当前状态CurrentState · 持有物Inventory | **结算层** | 结算域（唯一客观写入口） |
| 位置（坐标） | 代码（由地名/行程派生） | — |
| 表更新成本UpdateCost | **无人写** | 只读（gushi3/gushi4 两版一致） |

⚠️ **注意 gushi4 的一处行为改变**（需明确选定）：gushi3 的 N6 同时持有"玩家实况 + 感知 + 内心想法"，
所以它能用**客观真值**校正 NPC 的主观表（"玩家确实付了灵石 → 好感 +1"）。
gushi4 之后主观表只由角色层按**它自己的（可能是错的）认知**更新，**没有一层再用真值校正**。
这符合"失真"设计意图，但是**行为改变**——**必须显式选定，不能默认继承**。

## 1.C 事件生命周期（召集 / 踢出 / 散场遣散 / 新事件认定）

> 这一块是 gushi4 退步最明显的地方（`gushi4/移植缺口.md` §1.2、§1.3），也是玩家最容易感觉到的。

| # | 需求 | 判据与失败退路 | 验收 |
|---|---|---|---|
| **R-c·1** | 事件层每轮输出五件事：**是否新事件 / 进谁 / 出谁 / 直接对象 / 玩家移动目标** | 这五件是它的**全部**职责（一层一职，见 0.1） | 输出 schema 固定 |
| **R-c·2** | 新事件成立 → **同时**做三件事：(a) 清空**事件上下文** (b) 清空**参与者名单** (c) 清空**关联名单**。三者缺一 = 未散场 | 缺 (a) → 事件永不翻篇、输入无限膨胀、护栏失效 | 断言三者在同一轮都归零 |
| **R-c·3** | 参与者名单**不是只增**。玩家**换了地界**后，留在原地者必须退出 | 判据写死（在场/距离），不靠模型自觉；**点名的（传音/喊话）不受影响**（由"点名必达"当轮加回） | 移动两轮后名单里的人减少 |
| **R-c·4** | 「**在名单里但本轮不发声**」必须是**合法状态** | 若名单里的人在没人给他写感知时被**强制补一条**，名单就变成永久发声器 | 断言"不发声"这一状态可存在 |
| **R-c·5** | 名单里出现**不存在**的名字必须告警并丢弃 | 防幻觉 | 造一个假名 → 被丢 + 告警 |
| **R-c·6** | 防死循环护栏（上下文过短时不许宣布新事件）存在 | ⚠️ 它的判据依赖 R-c·2(a) 真的生效——上下文不清零时它**永久空转** | 护栏在"新事件刚清完"时能挡住 |
| **R-c·7** | 关系名单分**两份**（主动互动 / 行为关联），且区分**真的被下游用到** | gushi4 里 L1 算了这两份、注释说"供结算层区分被作用对象与在场旁观"，但**引擎从不读**——注释在说谎 | 下游确实按两份名单分流 |

## 1.D 位置与行程

> 这块是 gushi4 第二个退步点：`去向` 不持久 → 玩家说"继续赶路"**一步不动**（`移植缺口.md` §8 第三批）。

| # | 需求 | 判据与失败退路 | 验收 |
|---|---|---|---|
| **R-d·1** | 玩家位置**真源 = 坐标**；地名是**派生** | 派生字段不许被直接写（写了两版都栽过：写自由文本位置 → 那轮所有节点能力静默全失效） | 直接写地名 → 被告警丢弃 |
| **R-d·2** | **行程单持久化**：`{目的地, 出发地, 出发时刻, 预计总分钟}`。出发时写、抵达时清 | 不持久 → 玩家不能"继续赶路" | 连续两轮说"继续走" → 位置真的前进 |
| **R-d·3** | **「在路上」是状态，不是每轮要重新声明的意图**：行程单存在、且玩家**没报新地名、也没说停/不去** → 本轮移动目标 = 行程单里的目的地 | ⚠️ 只写"说'继续赶路'才沿用"**不够**——玩家换个说法（"我想出去放松一下"）就又停了 | 连续两轮不报地名 → 位置仍前进 |
| **R-d·4** | **推进比例由时间推**：`已过分钟 ÷ 预计总分钟` → 落在路线的哪个点。行程词（"半路/将到"）只做**覆盖或微调** | gushi3 是"几何→耗时"，这里是"**耗时→几何**"（见 0.3） | 时间在走则位置必前进 |
| **R-d·5** | 行程词**认不出**时，**不得**回落成"一步到目的地" | gushi4 现在的兜底是 `frac = 1.0` = 瞬移；数据铺得越多越容易瞬移 | 给一个乱词 → 位置**不动**而非瞬移 |
| **R-d·6** | 本轮耗时 = **单个数**（原地活动 + 赶路一起判），由结算层给 | 一层一个数，不要 gushi3 的"活动取大 + 移动相加"两段式（那是为了聚合多来源，现在只有一个来源） | 输出一个整数 |
| **R-d·7** | **耗时有上下界**：下限 1 分钟；上限按世界观配置，**超限截断并告警** | ⚠️ gushi4 只剩下限（`max(1, v)`）→ 一个幻觉数字能把时钟跳到几百年后且**不可自愈** | 给一个天文数字 → 被截断 + 告警 |
| **R-d·8** | NPC 的位置：**可被写**，或**显式声明为静态锚点** —— 二选一，必须写下来 | gushi4 隐形地冻结了它（没有任何路径能改），于是叙事说"他走了"、在场判定里他还在 | 二选一后测试断言 |
| **R-d·9** | 移动**只被客观拦阻中止**（物理拦住 / 门禁 / 受伤 / 路不通），且中止时**必须明说依据** | 见 R-b·9。gushi4 现在的形状是：NPC 只是问了句话，结算层却把玩家判成"站定未动"、+2 分 | 造一轮"NPC 只是说话" → 玩家照样前进 |
| **R-d·10** | 移动的**裁决权不落在会读 NPC 干扰的那一层**：位置推进由"行程单 + 时间"驱动（R-d·4），结算层只判**耗时**与客观拦阻 | 这是 gushi4 那个洞的根：把"我能不能走"从写盘动作变成了叙事判断 | 移动链路上没有"NPC 说什么"这一输入 |

## 1.E 感知失真

| # | 需求 | 判据与失败退路 | 验收 |
|---|---|---|---|
| **R-e·1** | 对每个在场的 NPC 写一份**它自己**感知到的内容，含对"这个玩家有多深"的**主观读数** | 这是设计枢纽 | 同一玩家在不同 NPC 眼里呈现不同侧面 |
| **R-e·2** | **不给刻度**：不得写"差几级就看不透"这类公式 | 给了 = 玩家能反推实力对比 = 越级战斗不可能 | prompt 审查 + 输出无刻度词 |
| **R-e·3** | 感知层**持有**玩家真值（否则无法失真），但输出**不得逐字出现**真值 | 检测到逐字复述 → **留痕告警**，不硬拦（高阶看穿是**正确**行为） | 告警带观察者自身修为 |
| **R-e·4** | 感知层**不替 NPC 下判断**：只写"发生了什么"+ 玩家深浅 | 替它判断 = 剥夺角色层 | 输出里无"何足挂齿"式的评价 |
| **R-e·5** | 感知层的**判断数**只许是：scope + 每人感知（含失真）+ 传闻传到谁 | 这是 0.1 的落点。**不要再往这一层塞事件名单**（那正是 gushi4 的病） | 层职责表 + 该层输出量监控 |

## 1.F 客观结算的唯一性

| # | 需求 | 判据 |
|---|---|---|
| **R-f·1** | 物品转移 / 伤害 / 位置变化本质跨实体，**双方同时变或同时不变** | 单方视角不可能完整 → 只有结算层能做 |
| **R-f·2** | 交易破裂时**注入一条「破裂观察」**，NPC 的反应下一轮由角色层自然发生（复用"观察→感知"通道，零新机制） | 不新造机制 |
| **R-f·3** | 属性/数值是**描述不是规则**：`危险=高` **不等于**"某人一定受伤" | 数值只记录结果、不参与叙事判断 |
| **R-f·4** | **越级战斗必须始终可能** | 不得用等级差公式算胜负 |

## 1.G 世界自走

| # | 需求 | 判据与失败退路 | 验收 |
|---|---|---|---|
| **R-g·1** | 心跳按**游戏时间**触发（间隔配置），独立线程，立即返回不阻塞 | 世界在玩家不说话时也在动 | 空转若干轮 → 后台有产出 |
| **R-g·2** | 后台产出**必须带状态**：已触发规则、已叙述主题；且**下一次调用要喂回去** | ⚠️ gushi4 里这两个缓存的写入与回喂**全断了**（字段只剩初始化）→ 同一条规则反复触发、同一氛围反复叙述 | 同一主题不得被叙述两次 |
| **R-g·3** | 候选筛选的理由集合要**写全**（含"区域事件"这类"所在地变了"的理由） | gushi4 从四种降到三种 → 世界某地变了，当地 NPC 不反应 | 造一次世界状态变更 → 当地 NPC 进候选 |
| **R-g·4** | 后台调度状态（各计时器、计数）**随存档保存、随撤回回滚** | ⚠️ gushi4 一个都不存 → 读档后计时归零、**一读档就触发** | 存档往返后计时不变 |
| **R-g·5** | 剧情级传播（跨地区情报流动）的输入里要带**本轮传闻传播结果**用于去重 | gushi4 拿不到它 → 与规则层传播重复 | 同一情报不重复写进观察表 |

## 1.H 地图与几何

| # | 需求 | 判据 |
|---|---|---|
| **R-h·1** | 几何只给眼睛：坐标 / 路径线**不进** LLM 输入；不得用几何算听不听得见、传多远、走多久、谁先动手 | 输入构造处审查 |

## 1.I 存档 / 撤回 / 新游戏

| # | 需求 | 判据与失败退路 | 验收 |

| **R-i·1** | 存档覆盖**全部会变的状态**，含：三种上下文、NPC 名单、玩家、世界、时钟、事件层、后台调度状态 | 列成清单，缺一项就有一条"读档后回不去" | 逐项往返测试 |

# 第 2 部分 · 不变量与已栽过的坑（**这就是"超越 gushi3"的可验收定义**）

每条格式：**如果新版本缺了它，这个症状会回来。**
前 5 条来自 gushi3 的规则层（那些是"曾经对过"的），后 10 条来自本次审计。

## 2.1 来自 gushi3 的规则层（别丢）

| # | 不变量 | 缺了会怎样 |
|---|---|---|
| **I-01** | **耗时有上界**（gushi3 是 100 年） | 一个幻觉数字把时钟推到几百年后，世界与 NPC 记忆相对玩家全部错位，**不可自愈** |
| **I-02** | **事件上下文在新事件时清空** | 事件永不翻篇；输入随游戏时长线性膨胀（**token 账单的计时炸弹**）；防死循环护栏永久空转 |
| **I-03** | **传播有 Python 兜底**：模型给不出可用的传播参数时，不得**静默**什么都不发生 | 某世界观的提示词没同步升级 → 玩家再也听不到任何传闻，且不报错 |
| **I-04** | **后台调度状态入档 + 随撤回回滚** | 读档即触发；撤回不干净 |
| **I-05** | **玩家的移动目标被持久记录** | 玩家说"继续赶路"一步不动（gushi4 现状） |

## 2.2 来自本次审计（gushi4 现在缺的）

| # | 不变量 | 缺了会怎样 |
|---|---|---|
| **I-06** | 凡声称"代码强制"的边界，代码里**真的有** | 判了"私密"却挡不住旁观者，秘密进了别人的观察表/记忆表——**不可逆，且不报错** |
| **I-07** | 「在名单里但本轮不发声」是**合法状态** | 名单变成永久发声器：你把某人留在原地走了，他每轮都回应你 |
| **I-08** | 参与者名单**会因走远而释放** | 一旦进过事件，就再也甩不掉（gushi4 现状：`involved` 只增不减） |
| **I-09** | NPC 位置**要么可写、要么显式声明为静态** | 叙事说"他走了"，在场判定里他还在原地，感知判定也还按旧位置算 |
| **I-10** | 叙事**去重缓存的写入与回喂**都在 | 同一处氛围被心跳一轮轮复制粘贴 |
| **I-11** | 已触发规则的**回喂**在 | 同一条世界演变规则反复触发，玩家可见叙述重复刷 |
| **I-12** | 客制化钩子（`{中文占位符}` ↔ `*_custom/*.md`）**配对完整** | 孤儿 md 成装饰；按世界观定制的那条静默退化成硬编码 |
| **I-13** | 「没人读的保留键」在**运行时**就能报（不只离线测试） | 手改配置时当场看不出拼错/写了没人读的键 |
| **I-14** | 每层**判几件事**有上限，且**不要为省往返而合并判断** | 最贵的那一层占关键路径 42%（gushi4 的 L1）；推理量涨、延迟涨、账单涨 |
| **I-15** | **测试不得掩护空壳**：断言要打在**机制**上，不是打在"容器能存住"上 | 空壳功能一路绿灯（gushi4 的 `smoke_test` 手工塞缓存再断言"往返一致"） |
| **I-16** | **移动默认继续**，且**只被客观拦阻中止**；NPC 的言语不构成拦阻 | 玩家报一次目的地之后，只要换个说法就会被判"原地不动"；而且 **NPC 一句台词就能当拦阻用**——实测：白鹤只是问话、动作意图是`无`，玩家却停住并 +2 分（`gushi4/log/gushi4.log` 第 1 轮） |
| **I-17** | **世界级事实只能来自数据或结算层的显式判定**；NPC 台词里的断言只是那个 NPC 的信念 | 任何 NPC 都能发明世界规则，且**一次就永久成立**（实测：白鹤编出"出山令牌"，`data/` 里根本没有这条；此后每轮都会读到它） |
| **I-18** | **参与者 ≠ 接收者**：`involved` 只表示"事件里有谁"，`scope` 表示"**本轮这条信息**给谁"。**边界执行只许做减法**（删掉不该收的人），不许做加法（给谁补一条） | 一条**私密传念**会被广播给事件名单里所有人，且各人以"玩家**对我说**"的口吻回应（实测：`gushi4/log/gushi4.log` 第 2 轮，4 个人回应了本该只有 1 人收到的传识）。再叠加 I-08（名单只增不减），**此后每条消息包括每条私密消息都发给所有进过事件的人**，他们一回应就进了全局上下文——**私密信息永久变成公开知识** |

# 第 3 部分 · 实现路径

## 3.1 推荐的分层（一层一职）

| 层 | 判几件事 | 输出形态 | 推理 | 预期墙钟 |
|---|---|---|---:|---:|
| **事件层** | 4 件（新事件 / 进 / 出 / 玩家去向） | 全是**名单 + 枚举 + 状态词** | **关** | ~2s ◻ |
| **感知层** | 2 件（scope + 每人失真感知） | 自由文本 | **开**（92%→58%，承重） | ~15s ◻ |
| **角色层 ×N** | 1 件（我这个 NPC 怎么反应） | 对白 + 心理 + 意图 | **关** | ~5s ◻（并行） |
| **结算层** | 1 件（客观怎么变 + 旁白 + 耗时） | 增量 + 数字 | **关** | ~1.5s |
| | | | **关键路径** | **≈24s ◻** |

**为什么这么划**：

1. **判断数是主因**（0.1）。gushi4 把"事件关系"与"感知分发"合进一层，那一层就变成判 6 件的
   最贵层（占关键路径 42%）。**拆开，各判各的。**
2. **推理开关按层单独定**。数据里只有一个"没测出质量代价"的提速来源：关角色层与结算层的推理
   （预计 1.59×），而**感知层的推理必须留**（关掉"看不透"式表达 92%→58%）。
3. **事件层的活全是名单和枚举，不需要想**——这正是 gushi3→gushi4 之间做过又退役的
   **"S1 轻判断通道"**（同模型 + 关推理 + 输出标量/枚举 + 失败走规则兜底）的形状。
   **把那个机制捡回来，用在事件层上。**
4. **4 跳但更快**：跳数是线性小项（每层固定基数被 cache 吃掉大半），判断数才是乘法项。
   所以"4 短跳"打得过"3 跳里有一个巨长的"。

⚠️ **本表除"结算层/角色层关推理"以外，全部标 ◻ 是估计**（依据是"判断数 → 推理量"这条外推，
没有实测）。**做出来第一件事就是量它**，并按实测量重划。

## 3.2 施工顺序

原则：**先把确定性外壳做出来**（能离线验收、不花 API），**再用 LLM 填判断点**。
每个阶段自带离线测试，进下一阶段的门是"本阶段测试全绿"。

| 阶段 | 做什么 | 验收门 | 花 API |
|---|---|---|---|
| **0 · 骨架与工具** | 目录、日志、配置读取、时钟（含上下界 R-d·7）、存档往返（含调度状态 R-i·1）、调试快照 | 时钟边界测试；存档逐项往返 | ❌ |
| **1 · 状态与地图** | 世界层（节点树 / 路段网 / 查询原语）、几何派生（在路上 R-h·3）、写盘三查 R-h·4 | 地图编辑往返逐字节相同；改一条只动一行；地点语义迁移基线 | ❌ |
| **2 · 确定性外壳** | 三种上下文 + 事件层的数据结构与生命周期（R-c·1…6）、参与者名单的释放规则 R-c·3、传播规则与兜底 I-03 | 事件散场三件事同时归零 R-c·2；走远即释放 R-c·3；"不发声"合法 R-c·4 | ❌ |
| **3 · 最小 LLM 回路** | 接入**结算层**（唯一客观写入口）+ **角色层**（1 个 NPC）。感知词先用"玩家原话"占位（**不失真**） | 单 NPC 单轮能跑通；越权写入被丢 R-a·3；表归属断言 R-b·5 | ✅ 少量 |
| **4 · 失真上电** | 接入**感知层**（R-e·1…5），去掉占位 | 同一玩家在不同 NPC 眼里呈现不同侧面；真值逐字复现 → 告警 R-e·3 | ✅ |
| **5 · 事件层上电** | 把阶段 2 的名单逻辑接到 LLM 判断上（**关推理**），多 NPC 并行、召集/踢出/散场 | 多 NPC 并行不串味；事件可散可聚 R-c·2 | ✅ |
| **6 · 位置与行程** | 行程单持久化 R-d·2、续行 R-d·3、时间推比例 R-d·4、认不出不瞬移 R-d·5 | 连说两轮"继续走" → 真前进；乱词 → 不动 | ✅ |
| **7 · 世界自走** | 心跳三件套 + 去重回喂 R-g·2 + 候选理由写全 R-g·3 + 调度入档 R-g·4 + 剧情级传播带传播结果 R-g·5 | 同一主题不被叙述两次；读档不立即触发 | ✅ |
| **8 · 前端与命令** | 终端 + 网页两个渲染器接同一接口 R-a·5；存档/撤回/新游戏 R-i·3…5 | 两端同一轮输出一致；新游戏后各层指向新对象 | ❌ |

### 每阶段都要守的两条纪律

- **加一层判断之前先问"这一层判几件事"**（I-14）。
- **删任何规则之前先指名替代者**（0.2）。删了没替代者 = 退回审计报告 §1。

## 3.3 把哪些测试当门（照 gushi3/gushi4 已有形状抄）

| 门 | 守什么 |
|---|---|
| **存档逐项往返** | R-i·1（含调度状态 I-04） |
| **信息域边界**（越权写入被丢） | R-b·1…5、I-06 |
| **地图编辑往返逐字节 + 改一条只动一行** | R-h·4 |
| **地点语义迁移基线**（与冻结基线逐条对照） | 换格式时的硬门 |

# 附录 · 与 gushi3 / gushi4 的取舍

## A. 从 gushi3 直接照抄（它是"对过"的那一侧）

- 事件层的**五件事**（新事件认定 / 召集 / 踢出 / 散场遣散 / 玩家移动目标）
- **散场 = 清名单 + 清事件上下文**（两件一起做）
- 三条**规则层**：耗时聚合（改成单来源，见 R-d·6）、传播判决 + 兜底、后台调度状态入档
- **S1 轻判断通道**这个**机制**（关推理 + 输出标量/枚举 + 失败走规则兜底）——用在事件层
- 客制化钩子和它的配对检查

## B. 从 gushi4 保留（gushi3 结构上做不到的）

- **三域划分 + 代码级边界**（`sanitize_*`）。gushi3 的隔离靠 prompt 约定，gushi4 靠代码
- **失真感知**（设计枢纽，有 92%→58% 的实验支撑）
- **结算层是唯一客观写入口**（修掉了"单方视角落实跨实体变更"这个结构洞）
- **几何只给眼睛**这条硬底线（虽然 gushi4 自己在若干处越界，见审计）
- 地图系统（扁平实体表 + 通路 + 段）与它的写盘三查
- 分层模型路由 / thinking 开关这套配置形状

## C. 明确不要（审计查出是坑）

- **不要**把"事件关系"与"感知分发"合进一层（I-14；这是 gushi4 最贵的一层）
- **不要**让名单只增不减（I-08）
- **不要**用"强制补一条感知"来保证"名单里的人不瞎"（I-07）
- **不要**在文档或 prompt 里声称代码会执行而代码没执行（I-06）
- **不要**删掉确定性规则而不指名替代者（0.2）
- **不要**让测试断言打在容器上而不是机制上（I-15）

## D. 必须显式选定、不能默认继承的三处

| # | 分叉 | 说明 |
|---|---|---|
| 1 | **NPC 主观表要不要被客观真值校正** | gushi3 会（N6 同时持有玩家实况）；gushi4 不会（角色层只有失真感知）。见 §1.B.1 |
| 2 | **"产出对白的那一层只能写 1 张表"这条纪律还要不要** | gushi4 放开了（角色层能同时决定说什么 + 改记忆/好感）。若当初的纪律是"防越权改表"，这是退步；若是"防信息泄漏"，防线在结算层身上，守住了 |
| 3 | **NPC 位置是否允许运行时改变** | gushi4 隐形冻结了它。若地图打算把 NPC 做成静态锚点，要**写下来**（R-d·8） |
