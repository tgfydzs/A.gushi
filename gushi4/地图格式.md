# 世界地图格式（草案 v0）

> **状态：草案。逐条否完才动手。**
> 本文只定**盘上的格式**与**它的解析/写回契约**。WEB 地图组件、编辑器的交互设计另文。

## 0. 它要同时服务四个消费者

| 消费者 | 要什么 |
|--------|--------|
| **引擎**（L1/L3/R4） | 结构：包含关系、属性、产出、通路。**不要几何** |
| **小地图**（游戏页常驻） | 几何：节点坐标、路段的路径线、范围的圈。**只读** |
| **编辑器**（同一个组件的另一种模式） | 双向：读出来改，改完写回去。**写回要保序** |
| **人**（手改） | 一行一物、能写注释、不用数括号和缩进层级 |

**范围**（这个词的两个意思见 §1.0 末尾）：`.map` 只管**地理与配置**
（`世界` / `配置` / `地点` / `路` / `段` / `坐标` / `路径线`）。
世界规则列表、世界状态、演变规则、世界知识**留在原来的 JSON**——它们没有几何、也不常手改。
这算"拆文件"的第一步，但**不绑定**：以后要不要按区域再拆 `.map`，是独立的事。

> 📖 **正式词从 2026-10-10 起统一**（定义与对照表在 §1.0）：**节点**（分为**地点**与**地区**）
> ＋ **路段**（两节点之间的连线，几何就是它的 `路径线`）。本文与其它几份材料里**历史段落**仍写的
> **"地块" = 节点**、**"区域/面" = 地区**、**"地段" = 节点**——那是旧词，含义不变。

一条贯穿全文的纪律：

> ⚠️ **几何只给眼睛，语义只给 LLM。** 节点的坐标与路段的路径线（折线点）**绝不进 L1/L3/R4 的输入**。
> 项目已经删过一轮"距离→结论"（R2 的段数折算、S1 旁路、R3 的距离过滤），
> 理由是"让 LLM 吐一个数字、Python 用表把数字翻译成结论，数字太窄，表就是那堵墙"。
> 坐标一旦喂进模型，它会立刻开始算距离，那条死路原路返回。

## 1. 两个族：节点 与 路段

**世界地图 = 节点 + 路段。** 就这两族，没有第三个。

| 族 | 是什么 | 判据 | 例 |
|----|--------|------|-----|
| **节点** | 一个**位置**。由它的**内部属性**（`类型`）再分成两种：**地点**（能停留的点）与**地区**（一块面） | 见下 | 天道宗 · 落霞坪 · 灵虚集（地点）；苍云大陆 · 东域 · 中州（地区） |
| **路段** | 两个节点**之间**的连线，它的点列就是 `路径线`。带**路段属性**；内部还可切出若干 `段`，每段带**段属性**（＝**途经**什么地形） | 只能**穿过**；停下才算到了别处 | `天道宗 ↔ 青木山脉` |

### 1.0 术语（正式词 ↔ 代码/文件里现在的名字）

| 正式词 | 一句话 | 代码/文件里现在叫什么 |
|--------|--------|----------------------|
| **节点** | 地图上的一个位置 | `地点` 行；扁平模型里的 `地块`（含 API 与编辑器页签名） |
| **地点** | 节点的一种：**能停留的点**，别人能在那儿找到你 | 不是地区的那些节点 |
| **地区** | 节点的另一种：**一块面**，由 `范围` 画出来。**不当路段的端点**（不能出现在 `从=/到=`） | `类型` ∈ {大陆,区域,域,州,疆域}；代码里 `is_region` / `REGION_TYPES` |
| **路段** | 两节点之间的**通路**。**路段属性**＝它自己的（`双向=` / `脚程=` / `| 说明`…） | `路` 行（几何是它的 `路径线`） |
| **段 / 段属性** | 路段**内部**的有序地形分段，**说的就是"途经"**（雪岭 / 溪谷 / 渡口） | `段 <名> : …`；**数据里现在 0 条** |

**三个词一次分清（2026-10-10 定）：**

- **`范围` 只是几何字段**（地区的那个圈）。节点种类叫**地区** → 不再有"范围两用"的问题
- **路段属性**＝整条路段的；**段属性**＝途经的那几段的
- **`地段` 这个词退役**，一律写**节点**：`地段传播` → `节点传播`、`当前地段` → `当前节点`、
  `地段属性链` → `节点属性链`、`地段能力` → `节点能力`（代码/提示词里还没改，见 `地图实施计划.md` §3.7）

**判据一句话：能停下来的就是地点，只能穿过的就是路段。**

> ⚠️ **两张图，别混。** `属于` 画的是**节点树**（谁属于谁）；`路` 画的是**路段网**（谁通到谁）。
> **`属于` 不是路段**——它是树的边，不是地图上的线。新人最容易在这儿搞混：
> 树边不进 `路径线`、不画在图上的实线里，也不参与"走多久"。

> ⚠️ 这里纠正了一个我先前的错说法。我说过"8000 米雪山值得是一个地点"——**不对**。
> 雪山可以穿越好几天，没有"站在雪山里"这个状态，它是**一条路段中的一段**（段属性＝途经雪原）。
> 像断云隘这种"能扎营停留的关口"，**作者可以**把它做成节点——但那意味着
> **路段在那里被拆成两条**。这是作者的取舍，不是引擎的判定。

由此推出两条简化（少两个概念，就少两处出错的地方）：

1. **一条路段只连接两个节点。** 要"经过第三个节点"，就写两条路段
   （`天道宗→灵虚集`、`灵虚集→青木山脉`）。于是 `途经=` / `经过=` 这些键
   **都不需要了**——上一版草案里的 `途经` 就此删除。
2. **路段内部由有序的 `段` 组成**，每段带自己的**段属性**（＝途经的地形）；段名供 `行进` 引用
   （"我在雪岭段的第二天"）。

**这条同时解决"在路上没有地点"**：位置格永远是**一个真节点**（走到哪算哪），
"在路上"是 `行进 = {路, 段, 已行, 预计}` —— 不是编一个字符串。

> ⚠️ **还剩一条没定（2026-10-10）：文件里的关键字 `地点`。**
> 按新术语，`类型=域` 的那些**不是**地点（是地区），可它们在文件里照样写成
> `地点 东域 : …`——关键字与含义对不上。两条路：① 改成中性的 `节点`；
> ② **两个关键字**（`地点` / `地区`），与节点种类一一对应，`类型` 就只剩"进一步细分"的用。
> 两条都是**格式改动**（碰所有读 `.map` 的地方 + 基线要重冻），**现在不改也行**：
> 语义由 `类型` 决定，关键字只是"这里开始一个节点"的意思。

### 1.1 行首关键字

文件是**行的序列**，每行以关键字开头。没有嵌套——层级用 `属于=` 表达。

```
世界    <名>                 : 键=值 …        # 一份文件只有一个
配置    : 键=值 …                              # 世界配置（原 global.json 的 世界配置）
地点    <名>                 : 键=值 … [| 描述]        # 节点：地点 或 地区，由 `类型` 分（§1.0）
路      <名>                 : 从=X 到=Y 双向=是/否 键=值 … [| 说明]   # 路段（这条行的关键字历史遗留地叫"路"）
  段    <名>                 : 键=值 … [| 说明]        # 必须紧随其所属的 路，缩进
坐标    <名> (x,y)                             # 可选（节点）；缺了就不画在地图上
路径线  <路名> [(x,y),(x,y),…]                 # 可选（路段）：点列，画那条弯路（前端平滑成曲线）
# 注释——**解析时丢弃**（见 §4）
```

`段` 是**路的子行**，只出现在 `路` 之后、缩进一级；段序 = 出现顺序。
`路径线` 沿用 `坐标` 的写法但名字不同：它画的是**线**，且点序 = 从起点到终点。

`|` 之后到行尾是**自由文本**，不参与键值解析（给 `描述`/`说明` 用）。**一行就是一行**——
不搞续行缩进（属性多就写长点，或者拆成多条自由键；少一条语法就少一处解析歧义）。

### 1.2 位置与几何（位置坐标化）

节点与路段都带几何——但**几何只给眼睛**。三样，一族一件（`段` 那件是派生的）：

| 几何 | 挂在哪 | 用途 |
|------|--------|------|
| `坐标`（点）＋ `范围`（圆/矩形） | **节点**（地区节点只有圈、没有点，见 §9.1） | 画图；判"某个坐标落在哪个节点的范围里" |
| `路径线`（**点列**，前端渲染成平滑曲线） | **路段** | 画那条弯路 |
| 段参数区间 `(t0,t1)` | `段` | 画"他走在雪岭段"。**贝塞尔不能按点序等分**，只能按参数 |

**画出来长什么样**（2026-10-10 定；判据是作者写的 `类型`，**不是"有没有子节点"**）：

| 节点 | 画什么 |
|------|--------|
| **地点** | 一个**实心盘**，盘的半径**就是它的 `范围`**——不另画一圈。于是"点了那个盘"和"那个地方有多大"是同一件事。名字仍按**一个小点**的高度往上让（盘可以很大：天道宗 r=104，名字飘到一百多个单位外就认不出是谁了） |
| **地区** | 把它的 `范围` 画成**虚线圈**、**不画点**，名字落在**圈心** |

所以"点的大小 = 范围"**只对地点成立**；地区的 `范围` 只是那个面有多大。
点击热区跟着同一个半径走（盘/圈多大就多大，另加 4px），这样"点看得见的那个"永远点得中。

**位置存坐标**（`当前状态CurrentState.位置 = (x, y)`）。但——

> ⚠️ **坐标是 Python 从语义派生的「表示」，不是 LLM 的输入格式。**
> L3 吐的仍然是**地名 / 去向**："我要往青木山脉去"、"本轮走到雪岭段中段"、"到了"。
> 由 Python 把它落成坐标。依据是原则 1/2：**状态的表示归 Python，判断才归 LLM**。
> 那次实测事故（L3 写 `青木山脉方向（离天道宗三日脚程）`）的根因，
> 恰恰是 L3 拿到了"表示的笔"。

由此**派生**、不必另存的两个量：

> ⚠️ **两条真源，各管一头，但必须一致。**
> `属于` 决定"谁属于谁"（喂 L1/L3 的节点链）；**`坐标`+`范围` 决定"他落在哪个节点"**（几何包含）。
> 两者不一致就会出现"**地图上他在 A 的范围内，LLM 收到的却是 B 的链**"这种鬼故事。
> 所以校验器**必须**报"子节点的范围越出了父节点的范围"——这不是美观问题，是一致性问题。


- **在哪个节点** = 最深的那层**包含他的范围**（包含链由几何得到）
- **在哪条路、哪一段** = 最近的路径线 + 该点参数 t 落在哪个段的区间
  → 于是上一版的 `行进` 字段**取消**（少一个字段，就少一处"坐标说在 A、行进说在路上"的不一致）

#### ⚠️ 「在路上」不能拿 `locate()` 当判据（2026-10-08 实测踩到）

自动布局给的 `范围` 半径是**画图**用的——区域圆要罩住子地块，于是天道宗 r=104、东域 r=252，
**整条路的走廊都落在某个区域的圈里**。用 `locate()['在路上']` 判的话，"在路上"**永远不会为真**
（实测：41 个地块坐标 0 个在路上，连路的中点也在某个区域的圈里）。

所以 `on_road_at()` 用一套**停留语义**的判据，与 `locate()` 分开：

| 序 | 判据 | 结果 |
|----|------|------|
| 1 | 落在某个**叶**地块范围内（叶 = 真能停下来的） | 就在那儿 |
| 2 | 离任何地块中心 ≤ `PLACE_CORE`(26) | 就当在那儿（区域枢纽也得有"站的地方"） |
| 3 | 离某条路 ≤ `ROAD_CORRIDOR`(40) | **在那条路上** |
| 4 | 都不满足 | 不在路上（退到"<最近地块>附近"） |

于是：**短路**（同门之间那几十个单位）基本判成"在天道宗地界内"——那是对的，你确实没走多远；
**长路**（跨域那几百个单位）中段才判成"在路上"，而那正是它有意义的地方。

`locate()` 本身**没动**（13 个调用点、迁移基线都依赖它）。改的只是"在路上"这个判断的出处。

### 1.3 点击移动：是"下令"，不是"瞬移"

小地图上**点地块 = 选中，再点「前往」才出发**（2026-10-08 从"点即前往"改过来）。
说是下令不是瞬移，指的是**机制**：点「前往」只发一句"我往X去"，坐标由 L3 判、代码落。
改手势是因为 41 个地块挤在一张图上，误点一下就是一次真实回合（花额度、推进世界）——
让"要去哪"和"去了"分成两步，成本才看得见。

**"不是瞬移"从 2026-10-08 起是真的了**（S3 / 1A.1）：L3 除了 `去向` 还要给一个
**语义进度** `行程`（`刚上路 / 半路 / 将到 / 到了`），代码按**整段路程的几分之几**把坐标
落在某条路的路径线上。所以：

- 去隔壁 → L3 说"半路"，玩家这一轮就**停在路上**（下一轮再"到了"）；
- 去远处 → `frac` 按整段算，中途那几跳**照样显示"在路上"**（因为它落在某条路上，
  而不是某个地块里）。一趟六跳的远门一轮就能走完，不必打六轮字。

⚠️ **认不出的 `行程` 一律按"到了"处理**（= 老口径"去向即到达"）。宁可多走一步，
不能把人卡在半路——那张词表是猜的，所以退化方向必须是"照旧"。
于是它顺手修掉 README 里那条已知缺陷（"点地点树会无条件把玩家移过去，瞬移不会被拒"）：
**远的地方不是"被拒绝"，而是要走、要走很多轮。**

**玩家与 NPC 共用同一套移动机制**：

```
语义意图（去哪） → L3 判（走哪条路 / 本轮到哪一段 / 是否到达） → Python 把坐标落到路径线上
玩家：点击地图、或打字              NPC：背景心跳产出意图（B2），下次 L3 落实
```

游荡**不着急**，所以 NPC 的移动延后一轮落地可以接受——它仍在后台线程里，不占关键路径。

**地图成为核心输入后，旧的那套移动机制全部退役**（✅ 2026-10-08 已完成）：

| 退役 | 它曾经为什么存在 |
|------|-----------------|
| `{移动}` 标记（`find_move_marker` / `resolve_move_markers` / `apply_move_target`） | 让**前端**给引擎一个"树上的合法路径"，好让引擎自己把位置写下去 |
| `/move` 命令 | 从来没生效过（README 已知缺陷） |
| `navigate_interactive()` 数字菜单、`/api/move` | 位置菜单的两个前端实现 |
| `engine.py` 里的**移动兜底**（直接用 `move_info['to']` 写客观字段） | 唯一的"绕过 L3 写位置"的口子 |
| `handle_input` 的 `need_move` 分支 | 把"选哪里"交回前端 |

**它们是同一个东西的影子：位置由前端提供、引擎照抄。** 改由 L3 出语义、Python 落坐标之后，
这个影子就没有理由存在——而且**终端版照样打字移动**（"我往青木山脉去"走的就是语义那条路），
**不损失任何能力**，反倒是少了一处绕过唯一客观写入口的地方。

> ⚠️ **纪律：几何距离只用于客观判定**（在不在场、落在哪个地块、前端邻近显示）
> 与 NPC 游荡的可行范围；**不得**用于听不听得见 / 消息传多远 / 走多久 / 谁先动手——
> 那些仍归 LLM。项目已经删过一轮"距离→结论"，别让它从几何这条门爬回来。

## 2. 示例（拿现有的世界改写一小段）

```
世界 苍云大陆·仙途诡道 : 起始时间=太初历三千七百四十二年·仲夏·午时  时间格式=时辰制
配置 : 生命值体系=数值  机缘_间隔_小时=0.5  机缘_每日上限=2  心跳间隔_小时=12

地点 苍云大陆   : 类型=大陆
地点 东域       : 属于=苍云大陆  灵气=浓郁  危险=低  势力=天道宗,星辰阁
地点 天道宗     : 属于=东域      灵气=浓郁  规矩=宗内禁私斗；外门弟子不得擅入内门
地点 落霞坪     : 属于=天道宗    功能=修炼,比试,交谈  危险=极低 | 炼气期外门弟子日常修炼之所
地点 灵虚集     : 属于=东域      灵气=稀薄  危险=低  功能=交易,情报,雇佣
                  规矩=坊市内禁斗；出了坊市概不负责
                  产出=低阶丹药:0.30 寻常法器:0.20 灵草:0.15 中品灵石:0.10
地点 青木山脉   : 属于=东域      灵气=浓郁  危险=中  功能=采药,采矿,探索
                  产出=灵草:0.25 粗铁矿:0.20 低阶妖兽内丹:0.10 野生灵参:0.03(深入山脉腹地)
路 天道宗-青木山脉 : 从=天道宗 到=青木山脉 双向=是  说明=官道出东门，翻过雪岭后沿溪下切
  段 官道 : 地形=官道  凡人脚程=半日
  段 雪岭 : 地形=雪岭  海拔=8000米 终年积雪 风急 隔阻=冬季封山  凡人脚程=两日
  段 溪谷 : 地形=溪谷  凡人脚程=半日
路 青木山脉-灵虚集 : 从=青木山脉 到=灵虚集 双向=否  凡人脚程=一日
  段 顺流 : 地形=水路  说明=顺流一日可达（这条只写顺流）
```

## 3. 键的规矩

### 3.1 保留键（引擎要读，写错=能力静默失效）

| 键 | 谁读 | 说明 |
|----|------|------|
| `属于` | 引擎 | 上级地点名。**包含关系靠它**，喂 L1/L3 的"节点属性链"靠沿它向上走 |
| `描述` | 引擎/小地图 | 当前地点描述（也可写成 `\| 自由文本` 形式） |
| `产出` | R4 | `物品:概率(条件)`，空格分隔多条 |
| `从` `到` `双向` | 引擎 | 路的端点（**只连两个地块**） |
| `段 <名>` | 引擎/L3 | 路**内部**的有序地形分段，作为子行出现。段名供 `行进` 引用 |
| `地形` `海拔` `隔阻` `凡人脚程` … | L3 | 描述性素材，写在 `路` 上或 `段` 上都合法。**给基准，不给换算表**——写"三日"可以，写"金丹×0.2"不行 |
| `坐标` `路径线` | 小地图 | 几何。**引擎侧一律不读** |
| `说明` | 小地图 | 路与段的解释文本，写在**行尾 `|`**（见 §4）。地块那一段叫 `描述` |
| `类型` | 小地图 / `is_region` | 大陆/区域/域/州 = **区域（面）**：只画范围圈、**不画点**、**不当路的端点**；其余值（山脉/冰原/宗门……）只是标签，仍是**地点**。缺省 = 地点（见 §9.1） |

> ⚠️ `地形/海拔/隔阻/凡人脚程` 那一行**曾经是假的**（2026-10-08 修）：
> `location_context_for()` 读的是 `road['属性']`，而 `roads()` 给的是**扁平**形状
> （属性摊在同一层，那是本文件的形状）——于是**永远取到空字典**，路的属性一个都没进过 L3。
> 当时每条路都只有 `自动生成=是`（正好在滤除名单里），所以从没暴露。修的时候顺手把
> **正在穿过的那一段**也带上了（段名 + 段属性）——段存在的理由就是"这一路穿过什么"，
> 以前它连段名都没进 L3。
>
> 同类的还有一处（同一轮修的）：`路 … | 说明` 解析进来就扔，手工写上去的说明保存即丢，
> 而写盘三查**拦不住**（模型里从头就没有它）。

> 这张表的每一行都由 `common/map_io.RESERVED_KEYS` 声明"谁读它"，
> 并由 `dead_reserved_keys()` 去代码里核对——**声明了却没人读的会被报出来**。
> 它抓到过一条真的：`类型` 原来的"谁读"一栏写着"引擎"，而代码里一个字都没有
> （2026-10-08 接上了，见 §9.1）。为什么费这个劲：手写的声明会撒谎，
> 而**撒谎的保留键 = 一个静默失效的口子**——项目栽过同款
> （`NPC_上限_MAX_MEMORY` 对不上 `NPC_记忆上限`，七项配置从没生效过）。

### 3.2 自由键

其余任何键都合法，值由 LLM 现场判断（Phase A 已定："缺的属性由 LLM 按世界观现场判断"）。
值的三种形态：字符串 / 数字 / `,` 分隔的列表。**要放进单值的逗号请用顿号或引号**。

> ⚠️ **已知风险：拼错保留键 = 静默失效。** `属于` 写成 `上级`，它就是个自由键——
> 解析不报错，能力却没了。项目里已经栽过一次同款（`NPC_上限_MAX_MEMORY` 对上
> `NPC_记忆上限`，**七项配置从来没生效过**，只因值恰好等于默认值才没暴露）。
> 对策见 §6：**近似键检测**。

## 4. 注释与"说明"的分工（GUI 保真的关键）

`#` 注释**解析后丢弃**：编辑器保存一次就没了。

想留下来的解释，写**行尾 `|` 后面那一段**：地块叫 `描述`、**路与段叫 `说明`**，
三者都是模型里的一等字段——文本侧与 GUI 侧都能编辑、都能活过保存。
这就是"手写文本"和"GUI 编辑"共用一份真源的前提：**凡是要活过保存的东西，就必须是数据**。

> ⚠️ **别写成 `说明=某字` 这样的键**：引擎只认行尾那个位置，写成键它就成了一条普通
> 属性（还会被当成节点属性喂给 LLM）。校验器会提醒这一条（见 §6 第 4 条）。
>
> 曾经这里是个**真丢数据**的口子：`路 … | 说明` 在 §1.1 的语法里写着，而代码
> **解析进来就扔**——手工写上去的一句话，保存一次就没了，写盘三查也拦不住
> （模型里从头就没有它）。2026-10-08 补上（解析 / emit / 表单 / 编辑器四个位置）。

## 5. 写回（emit）契约

编辑器保存 = 把结构 emit 成文本。硬指标：**保存后 `git diff` 只显示你改过的那一行。**

| 规则 | 内容 |
|------|------|
| 顺序 | 按**源文件顺序**输出；新增实体追加到该类别末尾 |
| 字段顺序 | 按**源字段顺序**；新增键追加到末尾 |
| 数值格式 | 统一规范化（概率最多两位小数），**在首次全量导出时就统一**，之后不再变 |
| 排版自由度 | **放弃**。空行、对齐、折行位置都由 emit 决定，不由源文件决定——换来 diff 干净 |
| 几何单独成行 | 拖一个点只改它的 `坐标` 行、拉一段只改它的 `路径线` 行，不动 `地点` / `路` 行 |
| **键序不许被顺手重排** | 顺序由**盘上那份文件**说了算，不由调用方说了算（见 §5.1） |
| **改名留在原位** | 改过名的实体待在它原来的行上，不甩到文件末尾（`canonicalize` 认改名） |

### 5.1 编辑器写盘：三查，不过就一个字节都不写

`map_io.save_map(path, edit, geo=…)` 是唯一的写入口，它按顺序做三件事：

| 查 | 做什么 | 不过的下场 |
|----|--------|-----------|
| 1 **结构** | `validate_edit`：`属于`/`从`/`到` 指向的实体存在、名字唯一、无空值、键不含分隔符、几何不悬空 | 不写 |
| 2 **往返** | `emit → parse → flatten` 必须回到**一模一样**的模型（内容**含键序**） | 不写 |
| 3 **备份** | 先复制到 `_备份/世界.map.<时间戳>`，再原子替换（写 `.tmp` 后 `os.replace`） | — |

第 2 查是这个项目里最值钱的一条：它挡的不是"写了一行坏的"，而是
**"改一条、顺手丢了另一条"**。落地当天它就抓出三个真 bug（tuple/list 不一致、
`产出` 写成了对象列表的字面量、两个构造函数键序不一致）。

**两道防线防重排**（不防的话"改一个字段 = 159 行 diff"，内容其实一字未改）：

- 服务端 `app.json.sort_keys = False`——Flask 默认**按键排序**，一排序编辑器存回就把整个
  文件重排了；
- `canonicalize(edit, base)`——落盘前把**实体序**与**每个实体的属性键序**按盘上文件对齐，
  盘上没有的新实体/新键追加到末尾。**所以新增是加法，不动老行**——哪怕调用方把键倒序送来。

**写盘前的整理抽成了 `map_io.prepare_edit(edit, base, geo)`**（拖拽几何 → 级联 → 保序对齐 →
DFS 排序），因为写盘之外还有**第二个出口"只看不写"**：编辑器的
`POST /api/map/preview`。编辑器左侧那张图是"开编辑器时拍的快照"，表单改了它不知道，
删过的线会留在图上（**看得见、点不动、也删不掉**）。预览拿表单走**同一条** `prepare_edit`
重算一遍再画 —— 于是"删地块连带删它的路"这类规则**只有 Python 那一份**，
前端不必在 JS 里抄一遍。预览不校验、不备份、不落盘、不碰运行中的世界，
它复用的画图函数是 `engine.map_view_of(w, st, location)`（线上那份 `map_view()` 也调它）。

**几何写坏了就不画**：`from_edit_form` 会把解析不出的那一条丢掉，照丢掉的画出来就是
"某块地凭空不见了"——比图旧一点难查得多。所以只要 `坐标/范围/路径线` 的条数与算出来的
对不上，预览就**拒答**（前端留着上一张图，打字停顿触发的那一次还不出声）。
字段行没写完之类**不拦**，那些不影响画图。

改名时预览**还要把改名映射报回来**（`{'地块': {旧: 新}, '路': {旧: 新}}`）：
图已经按新名字画了，表单里那串引用（`属于`/`从`/`到`/路名/几何键）也得跟着改，
不然"图上叫新名字的路"在表单里对不上，**点得中、选不中**。
配对仍然只由 `detect_renames` 做，前端只是把映射应用一遍。

### 5.2 改名与删除：级联，且一律说出来

编辑器只能改名和删除，**不能插入**（新建实体是阶段 3 的事）——所以"同一位置上名字变了"
就是改名，`detect_renames` 按列表位置比出来。位置信号有个**够不着的角落**：
**新建之后又改名**——新实体在盘上没有对应位置，位置比对轮不到它，它的 `坐标` 键就
还挂着占位名，落盘时被当成"悬空几何"**静默清掉**（新建的地块就此丢了坐标）。
所以补了一次按**几何键**的配对：一个没人认领的新几何键 ＋ 一个没有几何的新名字，
正好各一个，那就是一次改名。限 1↔1——多对多没有可靠的顺序信号，
宁可让用户看到"连带删掉"的提示，也不要配错（配错会把路接到别的名字上）。

| 动作 | 级联 |
|------|------|
| 地块**改名** | 子地块的 `属于`、路的 `从/到`、**路名（若它是 `A-B` 拼的）**、几何键 |
| 地块**删除** | 清掉它的 `坐标`/`范围`；**子地块挂到爷层**（删 天道宗 ≠ 删它下面 7 个地方）；端点没了的路连带删 |
| 路**删除** | 清掉它的 `路径线` |

三条纪律：

1. **顺序是先级联、后校验。** 反过来的话，"删一个地块"会在级联之前就被校验器拦下
   （它的几何悬空了），而级联本来就是来修那些悬空的——于是按钮永远点不通。真踩过。
2. **重名必须在最前面挡掉。** 级联与保序对齐都按名字配对，重名会让它们配错，
   最后报出来是一屏"属于成环"，跟真正的原因毫无关系（实测：把 `东域` 改名成 `苍云大陆`，
   报出 41 条成环、一条重名都没有）。
3. **有损的事一定要出现在返回里**（`cascade` 字段），界面上必须显示。
   之所以不做"先弹一次确认再删"：这个按钮原来的失败模式是**保存不了、也没有别处能删
   那行几何**——死路。**报出来的连带删除**比死路强，何况落盘前有备份、历史里有 git。

**端点空着 ≠ 端点没了**：前者是填错，交给校验器报错；后者是删地块的后果，才连带删路。
混起来的话，用户删到一半（端点暂时空着）会静默丢掉整条路。

### 5.3 热重载：三分类，不说一句笼统话

`gc.reload_world()` 返回**按"什么时候生效"分三类**，不再回一句"已保存并热重载"
——那是把三种情况说成一种，比报错更糟（用户会以为改了 `NPC_上限_*` 就生效，然后奇怪它没变）：

| 类 | 内容 |
|----|------|
| **立即生效** | 地点 / 路 / 几何 / `NPC_上限_*`（**类属性**，必须重跑 `apply_config_caps` 才真生效） |
| **需重启** | `玩家初始数据`、`游戏开始时间`、`时间格式`（时钟对象开局就建好了） |
| **一直成立** | 改 `产出` 或节点属性**不会重算场上 NPC 已有的记忆** |

⚠️ `游戏开始时间` / `时间格式` 是**顶层键，不在 `世界配置` 里**——只比 `世界配置`
会把"改了开局时刻"算成"没有变动"。两处一起比（`map_edit_test` / `ui_test` 都盯着这条）。

编辑器与 `.map` 之间的**线上形态**（`to_edit_form` / `from_edit_form`）刻意不送原生 JSON，
而是**每个值都写成它在 `.map` 里的样子**：`[a,b]` 是列表、`是`/`否` 是布尔、纯数字是数字、
`产出` 是 `物品:概率(条件)`。理由是类型规则只该有一份（`_parse_value` / `_fmt_value`，
它们被往返测试钉死了）——前端再抄一份就是两处真相。顺带好处：字段框里显示的就是
"这一条写进 `.map` 会是什么样"，用户看着就会写。

1. **语法**：报行号。✅ `parse_world`
2. **引用完整**：`属于` / `从` / `到` / `坐标` / `路径线` 指向的实体必须存在。✅ `validate_edit`

4. **键写歪了** ⚠️：✅ `key_notices()`，**只提醒、不拦保存**，三副面孔：
   - **像保留键**：`类形`≈`类型`、`属於`≈`属于`、`双方`≈`双向`（编辑距离 ≤1，含换位）；

     一个共同字都没有，编辑距离是 2，纯字面比对永远抓不到；但它**想干什么**看得出来。
5. **死键报告**：✅ `dead_reserved_keys()`——核 `RESERVED_KEYS` 里"谁读它"那句声明，
   声明了却搜不到的报出来（现在报的是 `类型`）。这是**弱检查**（字符串拼出来读的键它查不到），
   但正好挡住最要命的那种谎。
6. **全库位置引用自检**：✅ 在 `src/test/map_migration_test.py` 里：扫 `data/` 下的 NPC 档、
   玩家档、存档、剧本、测试数据，凡是位置字符串在新格式里解析不出来的**全部列出**。

## 7. 位置与改名

- 位置对外仍是**路径字符串**（`苍云大陆·东域·青木山脉`）——可读、可写、可 diff，
  存档里存的就是它。**内部键也就是它**（名称即键）。
- 因此**改名 = 迁移操作**：编辑器里改名必须同时改写存档与"在路上"的引用。
  编辑器里不提供"静默改名"。

映射：

| 旧 | 新 |
|----|----|
| `世界地点列表` 的每个节点 | 一行 `地点`（名 = 原键名） |
| 父子嵌套 | `属于=<父名>` |
| 节点里的 `_属性` 每个键 | 平铺成同行的字段 |

### ⚠️ 路从零开始

旧世界里只有地块、**没有任何通路**——所以迁移后的地图是**一堆点、一条线都没有**。
两条路可选（**要你定**）：

- **留空**：点之间没有连线，路全部手画。诚实，但小地图会很空，而且"从 A 到 B"在数据上不成立。
- **自动补一层骨架**：同父下的直接子节点互连 + 父↔子各一条，双向，脚程**留空**
  （交 LLM 现场判断），每条标 `自动生成=是`。人工再删改。

**我倾向第二条**——空地图连"弯路"都没得画，何况 `自动生成=是` 让"哪些路是凑数的"一目了然。


**验收方式：先冻基线，再换形状。**

1. 迁移前，用旧代码导出一份**行为快照**：全部路径集合 + 每条路径的属性 + 出生点属性链。
2. 迁移后逐条对照——**一模一样才算演化成功**。
3. 通过后旧断言（`location_test` 58 项）退役，同时删除：`normalize_node` 保留键机制、
   `_walk_path` 最长匹配、`parse_path`、`location_depth/distance`、
   `find_npcs_at_location` 的段数近似。

### 9.1 地区与地点分家（**已定：按下面的推荐版落地，2026-10-08**）

> 📖 这一节 2026-10-08 写的时候管"面"叫**区域**；2026-10-10 统一术语后正式词是
> **地区**（节点的一种，见 §1.0；它由 `范围` 画出来）。下面文字里的"区域/面"= 地区，
> 含义一字未改。

现在的形状：**41 个节点里 13 个是范围**（苍云大陆 r=668、南域 310、东域/西域/北域 252、
中州 164…），却和叶子一样**只有一个坐标点**。`属于=` 已经表达了包含关系，
**被迫给一个点的是几何**——`坐标` 是唯一"他在哪"的原语，画图和当路段的两端都要它。

代码里**已经留好了那个字段**：`类型`（§3.1 写着"大陆/区域/地点…供小地图与外层判断"）。
问题是它**数据 0 条、代码没人读**——正是 §6 第 5 条报出来的那个"空头承诺"。

**我的方案（推荐）**：用 `类型` 把"面"和"点"分开，**不新增族**：

| | 地区（`类型=大陆/区域/域/州/疆域`） | 地点（默认） |
|---|---|---|
| 位置 | **是一块面**：有 `范围`；`坐标` 只当**范围圆心**（画图用），**不是落脚点** | 有坐标点，能停留 |
| 路 | **不许当路的端点** | 路的端点只能是它 |
| `产出`/`功能` | 不该有（它不是个能去的地方） | 可以有 |
| "去 X" | `去向` 给区域名时**不落点**：代码把它解析成**域内一个具体地点**（先给一条最简单的规则：**子树里离玩家最近的那个叶地块**），把实际落脚点写进位置 | 直接落点 |

配套两条（⚠️ 第一条 2026-10-10 改过，见下）：
- 校验器加一条**提醒级**规则：**标了地区却又带 `产出`/`功能`**、或者**地区被当成路段端点**——
  判定"谁是地区"**不靠猜**，靠作者写的 `类型`。（原本还有一条"有子地块却没写 `类型`"
  的提醒，2026-10-10 删了：地点完全可以有子节点，天道宗就有 7 个，那条会在正经数据上一直叫。）
- `locate()`/`nearest_place`/`on_road_at` 要**跳过区域**（否则"站在苍云大陆圆心"仍然成立）。

**代价（说实话）**：现在这批路里，端点是大区的那些（`苍云大陆-东域` 之类）**要重连**
到区域里的具体地点——而"重排坐标与路"正是**修订地图**那一次要做的事，所以这件事
**挂在那一次一起做**最省事：现在只把规则写进文档、把校验器做成提醒，等数据到位再升级成硬规则
（现在升成硬规则会让编辑器存不了盘）。

**最小改动版**（只想先让图好看）：区域**不画点**（只画范围圆圈），其它照旧——
0 数据迁移，但"去东域"仍然落在放射中心上。**两个版本的差别只有那一点语义**。

#### 落地情况（2026-10-08）

**机制全在了，数据还没补**——所以现在一行行为都不变（`类型` 缺省 = 地点）：

| 位置 | 做了什么 |
|------|---------|
| `B1WorldLayer.is_region()` | `类型` ∈ {大陆, 区域, 域, 州, 疆域} → 区域。**不猜**（天道宗有 7 个子地块，可它能停留） |
| `locate()` | 区域不参与"落在谁的范围里"；另给 `区域`（脚下那个面）与 `野外`（离最近地点比"站在那儿"还远） |
| `location_desc()` / `location_context_for()` | 加了**野外**分支：`（在东域的旷野上）` + 明写 `不在任何地点` + 区域那条链照给（灵气/危险）。**不假装他在最近那个村子里** |
| `map_view_of()` | 每个地块多一个 `region` 标记；前端据此**不画那个点**（圈、名字、命中区照旧——照样点得中、选得中） |
| `key_notices()` | 三条提醒：`类型=区域` 却有 `产出` / 带子地块却没写 `类型` / **区域被当成路的端点** |

**"llm 侧会不会误判"**——分两种：

- **不会**：能不能听见、走多久、谁先动手、属性链（灵气/危险/规矩）——这些走 `属于` 层级
  或与"点"无关，区域有没有那个点都不影响。**图的点只是画出来的圆心。**
- **要小心的一处（已处理）**：`locate()` 原来会把"野外"**静默塌缩**成"最近的地块"——
  去掉区域的点之后，站在旷野上的人会被说成"就在最近那个村子里"，**正是 2026-10-08
  那次事故的形状**。所以分家必须**连野外状态一起给**（上表第 3 行），而不是只删掉点。
- **✅ 2026-10-10 落地**：`去向` 给**地区**名时，代码把它解析成域内一个**具体地点**
  （最简规则：子树里离玩家最近的叶节点）——`B1WorldLayer.stop_in()` 干这件事，
  `GameController.set_position()` 调用它，所以**只有一处**（位置唯一的写入口）。
  地区底下**一个地点都没有**（整片荒野还没写具体地点）→ **原地不动 + WARNING**，
  不编一个假位置。
- **同时补上的两件事**（都在 2026-10-10）：
  - 真文件里**第一次有了地区**：作者给 苍云大陆 / 东域 / 西域 / 南域 / 北域 / 中州
    写上了 `类型`（值就是 `REGION_TYPES` 里现成的词）。判据从"看着像"变成"作者写"。
  - 校验器**删掉了一条**旧提醒："有子地块却没写 `类型`"——它当时的前提是
    "带子节点 = 看着像区域"，而**地点完全可以有子节点**（天道宗有 7 个），
    那条会在正经数据上一直叫。留下的是：地区带 `产出`/`功能`、地区被当成路段端点。

### 9.2 要不要把"路的长度"喂给 L3（**已定：先不喂，看效果**，2026-10-08）

现状（2026-10-08 已落地）：L3 出 `行程`（**语义**：刚上路/半路/将到/到了）→ 代码映射成
"整段路程的几分之几"→ 落坐标。**L3 拿到的是路的语义属性**（`地形`/`海拔`/`隔阻`/`凡人脚程`，
`location_context_for()` 在路上时第一条就是它们），**一个数字都没给**。

所以"让 LLM 出一个进度"**已经是现在的做法**。差别只在一处：**要不要把算出来的长度也喂进去**。

**我倾向不喂**，三条理由：

1. **现在的数是画图值**。`坐标` 出自 `auto_layout()`（自称"只是初值"），`南域-北域` 有 680
   单位只因为树里是兄弟——算出来的长度**没有意义**，而它马上要跟你一起重排。
2. **一个标量表达不了"路上有什么"**，而 L3 需要的是后者。`海拔=8000` 的雪岭、溪谷、渡口
   ——这些是**段**要装的东西，也正是"能不能过、几时到"的真正依据。
3. **给刻度就等于给公式**（与 §2.3 失真感知同一条纪律）。一旦 L3 拿到"680"，
   它就会开始算"三百里、两日脚程"，而那个数字是我们编的。

**要长度也可以，但它的消费者应该是代码、不是 LLM**（比如以后 NPC 游荡的节流）。
真要给，形状是给 `脚程` 这类**作者写的语义**（"半日"），让它自己对世界下判断——
`脚程` 现在 0 条，就是这个位置空着。

#### 段：怎么铺、什么时候铺（2026-10-08）

**先接上"段名当进度"，再铺段数据**——顺序不能反：

`行程` 报段名（"走到雪岭了"）时，`travel_frac_by_segment()` 会把它折算成整段路程的 frac
（只认**第一跳**那条路上的段；段名去掉「段/一带/之地」尾缀也认）。**没有这一步的话**，
`_STAGE_FRAC` 认不出 → 退回 `frac = 1.0` ＝ **一步到目的地**——段数据铺得越多，
L3 越会照着段名说，**越容易瞬移**。

铺的原则：**只给真有地形的少数路写**（`海拔=8000` 的雪岭、溪谷、渡口、西漠、极寒冰原），
别给每条路都凑三段——凑出来的"第一段/第二段"进了叙事就是噪音。段名要能进句子里。

区间：段可以自己写 `区间=[t0,t1]`（几何字段），没写就按**段序等分**（`segment_ranges()` 一处说了算）。

### 10.3 重置当天会咬人的四处（都是实测出来的）

| 坑 | 现象 | 怎么办 |
|----|------|--------|
| **`世界.map` 没进版本库**（untracked） | 一次 `--relayout` 就能把调了半天的坐标抹掉 | 命令现在都会**自动备份**；开始前先 `git add` 一次 |
| **`世界` 与 `配置` 两行最容易漏** | 整张重写时忘了抄 `配置` 行 → 引擎**悄悄退回默认值**（比如机缘照开）——不报错 | 校验器会提醒"配置里引擎要读的键一个都没有"；手写时整行抄过来 |
| **档里的位置指向旧地点** | `data/player`、`data/B3_npc`、存档里的 `当前所处位置` 在新图上解析不出：旧坐标会落到"最近的地点"（可能几百单位外，界面会说"在旷野上"）；只有路径没坐标的老档会变成**位置为空** | 重置后先看 `/api/state` 的 location；跑 `map_migration_test.py`（**扫全库位置引用**，列出来）；再把档里的位置改到新地点。**这一步是人定的，代码不代劳** |
| **`--layout` 的坐标不是地理真值** | 它是**画图初值**（`auto_layout` 自称"只是初值"），只保证不重叠 | 真位置在编辑器里拖出来 |

**两条不要做的**：

- **别在编辑器里点 40 次「＋新建地块」**——那是给"补一块地"用的。从零起就**手写文本**。
- **别把几个动词串在一条命令里**（`--drop-geo --layout` 这种）：它们各自要写盘，
  现在会提示"一次只做一件事、按第一个来"。分开跑。

**重置期间的两条保险**（2026-10-08 加）：

| 情形 | 行为 |
|------|------|
| 地图上漏了一条路（某个地点成了孤儿，手写新世界时几乎必然发生） | 玩家去那儿**不会卡住**：直接落点 + 一条 WARNING 说"这是数据的漏"。**不编假位置**（不存在的名字照旧不动） |
| 区域还挂着路（骨架路就会这样） | 校验器列出来（"N 个区域被当成了路的端点"），但**不拦保存**——重置期间它就是草稿 |
